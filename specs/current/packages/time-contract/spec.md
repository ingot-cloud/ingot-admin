# 统一时间契约规格

## 概述

列表、详情、锁定期限、授权有效期及名单等时间点统一使用带 `Z` 或偏移量的 ISO-8601。模型保存原始 ISO，共享时间工具在展示与选择边界转换，不扫描或重写普通 JSON 字符串。接口细节见归档 [API.md](../../../changes/archive/2026/20261008-packages-time-contract/API.md)。

## 用户场景

### 场景 1：在当地查看同一时刻

- **角色**：平台、租户或会员用户
- **步骤**：在列表或详情查看时间点
- **预期结果**：按浏览器当地时区显示，识别失败回退 `Asia/Shanghai`；默认格式为 `yyyy-MM-dd HH:mm:ss`，工具支持显式指定展示时区

### 场景 2：选择并保存截止时间

- **角色**：具有相应维护权限的管理员
- **步骤**：从原 ISO 模型打开 DatePicker，按当地时间选择后保存
- **预期结果**：选择提交为 UTC ISO；相同瞬间的不同偏移输入等价，原模型的精度不因只读展示而丢失

## 功能需求

### REQ-001：严格收发时间点

系统 MUST 以带时区的 ISO 保存和提交时间点，响应使用 UTC `Z`。JSON、query、form 遵循相同契约；无时区、旧格式和非法输入由接口返回 400。

### REQ-002：显式转换边界

系统 SHALL 使用共享工具解析时间点、格式化当地展示和转换 DatePicker 选择。模型不得保存已经格式化的墙钟字符串。空选择省略，非法选择不提交。

### REQ-003：保留其他时间语义

系统 MUST 保留日期、日内时间、Duration、Cron 与 JWT/OAuth 数字时间的独立语义，不将它们按普通时间点转换。BFF 事务 `expiresAt` 按接口 ISO 时间点读取，协议 `expires_in`、TTL 和内部秒/毫秒时间戳保持数字语义。

## 兼容性与依赖

- 前后端成套切换；旧 API 时间格式不再支持，回退需配套前后端版本和配置
- 本次不迁移历史数据库、Redis 或队列数据，不增加时区设置页面
- 后端判断和存储使用 UTC；前端契约与接入说明见 [时间规范](../../../../docs/time-contract.md)
