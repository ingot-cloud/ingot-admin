# 详情查看/编辑标准规格

本文写已上线的页面与共享组件行为。接口细节见归档 [API.md](../../../changes/archive/2026/20260907-packages-detail-edit-pattern/API.md)，不要在此维护完整接口表。

## 概述

管理台实体详情默认只读，由底部按钮进入编辑；编辑中关闭抽屉或切换 Tab 必须确认。页内 Tab、身份区、只读描述、确认框与操作下拉为 `@ingot/admin-core` 标准。通讯录成员与部门已接入；添加成员、添加部门仍为创建表单。

## 范围

### In Scope

- `InBizTabs` 墨条与 `before-change`
- `InDetailDrawer`、`InDetailIdentity`、`InDescriptionList`、`useDetailEditSession`
- `InDrawer` 的 `layout="pinned"`
- 公共确认框（`Confirm` / `openConfirmDialog` / `InDialog`）
- 操作下拉（`.in-dropdown` / `.el-dropdown__popper`）
- 通讯录成员详情与添加成员拆分
- 通讯录部门详情与添加部门拆分

### Out of Scope

- 上一个/下一个、别名、工位、工号、自定义字段、发送提醒
- 角色、会员用户、平台管理员等其它详情抽屉迁移

## 用户场景

### 场景 1：查看成员详情

- **角色**：组织管理员
- **前置条件**：已登录，打开通讯录成员列表
- **步骤**：点击行「详情」或头像
- **预期结果**：右侧抽屉标题为「成员详情」；身份区展示头像、姓名、账号状态和「更多操作」；基本信息只读；底部为「编辑基本信息」

### 场景 2：编辑基本信息

- **角色**：组织管理员
- **前置条件**：成员详情处于查看态
- **步骤**：点击「编辑基本信息」，修改后保存或取消
- **预期结果**：字段变为表单；底部为「取消」「保存」；取消回到查看态并丢弃未保存修改；保存成功后回到查看态并刷新列表。编辑态可悬停身份区头像上传，表单不再单独出现头像项

### 场景 3：编辑中离开

- **角色**：组织管理员
- **前置条件**：成员详情处于编辑态
- **步骤**：关闭抽屉、按 Esc 或切换 Tab
- **预期结果**：弹出「确定退出当前编辑？」；说明「退出后，修改的内容不会被保存」；无右上角关闭按钮；取消留下，确定丢弃并继续

### 场景 4：更多操作

- **角色**：组织管理员
- **前置条件**：成员详情已打开
- **步骤**：点击「更多操作」，选择暂停/恢复或删除
- **预期结果**：菜单右对齐展开，无箭头、条目间无分割线；暂停/恢复与删除走公共确认框；成功后刷新列表，删除后关闭抽屉

### 场景 5：添加成员

- **角色**：组织管理员
- **前置条件**：成员列表工具栏可见
- **步骤**：点击「添加成员」，填写并提交
- **预期结果**：打开独立创建表单，不进入查看态

### 场景 6：查看部门详情

- **角色**：组织管理员
- **前置条件**：已登录，打开通讯录部门列表
- **步骤**：点击行「详情」或部门名称
- **预期结果**：右侧抽屉标题为「部门详情」；身份区展示固定部门头像、名称和状态，头像不可编辑；基本信息只读；底部为「编辑基本信息」

## 功能需求

### REQ-001：页内 Tab 墨条

系统 SHALL 提供飞书式页内 Tab：16px 字号、默认主文字色、选中主色、3px 活动条跟随选中项。

**验收标准：**

- [x] 默认色使用 `--in-text-color`，选中色使用 `--in-color-primary`
- [x] 活动条可见高度 3px，宽度与选中文案同宽，顶部圆角，半条压在底部分隔线上
- [x] `before-change` 返回 false 时不切换
- [x] 遵守 `prefers-reduced-motion`

### REQ-002：详情抽屉标准壳层

系统 SHALL 在 `@ingot/admin-core` 提供查看/编辑详情抽屉标准。

**验收标准：**

- [x] 查看态底部只出「编辑{当前分组}」主按钮；编辑态出取消与保存
- [x] 编辑态关闭或切 Tab 必须确认；文案为「确定退出当前编辑？」；`showClose: false`
- [x] identity 与 Tab 钉住，仅字段区滚动
- [x] 普通 `InDrawer` 默认滚动行为不变

### REQ-003：只读描述与身份区

系统 SHALL 提供上标签下值的只读列表和大号身份区。

**验收标准：**

- [x] 空值显示 `-`，不用 disabled 输入框冒充只读
- [x] 身份区为大号头像、姓名、状态槽和右侧更多操作槽
- [x] 编辑态头像在身份区悬停上传，不在表单里再出头像字段

### REQ-004：公共确认框

系统 SHALL 提供统一的公共确认框，供命令式 `Confirm` 与声明式 `InDialog` 共用同一视觉。

**验收标准：**

- [x] 对话框在视口水平、垂直居中
- [x] 内容可以是文案或自定义 VNode / 默认插槽
- [x] 右上角关闭按钮由 `showClose` 控制，默认显示
- [x] 标题左侧图标可自定义或隐藏；`Confirm` 默认按语气显示填充图标
- [x] 白底、8px 圆角、标题色 `--in-text-color`

### REQ-005：操作下拉菜单

系统 SHALL 提供统一的操作下拉：无箭头；标准操作菜单无条目分割线。

**验收标准：**

- [x] 容器使用 `--in-border-color`、`--in-radius-control`、`--in-shadow-overlay`、`--in-text-color`
- [x] 不显示 Popper 箭头
- [x] 成员详情「更多操作」右对齐展开，条目之间无分割线

### REQ-006：成员详情试点

通讯录成员详情 SHALL 接入该标准；添加成员仍为创建表单。

**验收标准：**

- [x] 详情默认只读；查看态与编辑态字段顺序一致：姓名、手机号、email、部门
- [x] 头像只在身份区展示与更换
- [x] 更多操作仅暂停/恢复与删除；成功后刷新列表，删除后关闭抽屉
- [x] 不出现上一个/下一个或平台没有的飞书字段

### REQ-007：部门详情接入

通讯录部门详情 SHALL 接入该标准；添加部门仍为创建表单。部门头像固定为 `deptDrawerHeaderAvatar`，不可更换。

**验收标准：**

- [x] 详情默认只读；查看态与编辑态字段顺序一致：部门名称、部门 ID、上级部门、部门主管、状态
- [x] 身份区使用 `deptDrawerHeaderAvatar`，`editable=false`
- [x] 更多操作仅删除；成功后刷新列表，删除后关闭抽屉
- [x] 根部门不可打开详情；添加部门仍为独立创建表单

## 非功能需求

- 颜色与动效走 Token，组件内不写死品牌色
- 共享组件公开属性保持文档化，供后续详情抽屉接入

## 依赖与约束

- 成员试点复用既有组织用户 CRUD，不改接口契约
- 部门详情复用既有组织部门 CRUD，不改接口契约

## 验收标准

- [x] 成员详情默认查看、底部进入编辑、离开需确认
- [x] 添加成员仍为创建表单
- [x] 部门详情默认查看、底部进入编辑、头像不可更换
- [x] 添加部门仍为创建表单
- [x] 公共确认框与操作下拉为平台标准样式
