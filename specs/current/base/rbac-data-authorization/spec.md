# RBAC 与数据授权规格

本文写已上线的页面行为；接口细节见归档 change 的 [API.md](../../../changes/archive/2026/20260911-base-rbac-data-authorization/API.md)，不要在此维护完整接口表。

## 概述

PMS 以「菜单可见性 / 功能权限 / 资源数据范围」三套事实来源驱动管理台。登录后并行 bootstrap 用户资料、可见菜单和有效权限各一次；侧栏与动态路由只吃菜单树，页内按钮与表格操作只认已展开的具体权限码。平台配置应用默认访问策略与资源目录，菜单改为关联 ACTION 权限列表，权限树只认 `nodeType`；平台角色写平台默认数据规则，组织角色只写本租户追加层。

## 范围

### In Scope

- `packages/admin-core`：会话 bootstrap、权限 store、路由守卫、`v-auth`、表格操作过滤、HTTP 403 / 503
- `plugins/platform`：应用（含 `defaultAccessMode`、资源 Tab）、菜单（`permissionIds` + `permissionMatchMode`）、权限树（仅 `nodeType`）、平台角色 data-rules
- `plugins/org`：租户角色绑权树字段、租户层 data-rules；角色表单不再使用单条 `scopeType` / `scopes`

### Out of Scope

- `plugins/member` 会员权限树（独立服务，仍可保留 `AuthorityTypeEnum`）
- 登录应用 OAuth2 流程（切组织仍走重新登录，自然触发 bootstrap）
- 前端行级过滤或 demo 订单页
- 按 `expiresAt` 做定时轮询

## 用户场景

### 场景 1：登录后拿到可用按钮

- **角色**：任意已登录用户
- **前置条件**：进入 `apps/admin` 后的首次需鉴权路由
- **步骤**：并行请求用户资料、可见菜单、有效权限各一次；侧栏渲染服务端已过滤的菜单树；页内按钮 / 表格操作按有效权限码显示
- **预期结果**：`info` 不含业务权限码；菜单无 Button 节点；按钮码来自 `permissions` 展开后的具体码。后续路由切换不再重复打这三个接口

### 场景 2：撤权后界面可暂时不准，请求仍被拦住

- **角色**：已被撤权但仍开着页面的用户
- **前置条件**：任意已登录业务接口
- **步骤**：不按 `expiresAt` 定时轮询。窗口重新可见且本地已过 `expiresAt` 时可再拉一次权限；业务接口 403 后再拉一次以藏掉按钮；503 快照不可用提示稍后重试并再拉一次
- **预期结果**：真正拦请求的是业务 API；按钮晚消失、点了 403 属预期。503 不清空权限、不登出

### 场景 3：配置应用与资源

- **角色**：持有应用配置权限的平台管理员
- **前置条件**：打开 `/platform/config/app`
- **步骤**：创建应用时选择默认访问策略（开放 / 申请制）；详情「资源」Tab 维护资源目录；权限节点可绑定 `resourceId`；不要手动创建或删除应用根权限
- **预期结果**：列表 / 详情 / 创建 / 更新都能读写默认访问策略；资源 CRUD 可用；仍被引用的资源删除失败并展示后端中文 `message`

### 场景 4：配置菜单可见性

- **角色**：平台应用管理员
- **前置条件**：应用详情「菜单」Tab
- **步骤**：菜单类型只有目录 / 菜单。受保护页面多选同应用 ACTION 权限，并选择 ANY / ALL；目录和开放页禁止关联权限。可先快捷新建权限再勾选
- **预期结果**：保存不传旧单权限字段、不提供按钮类型；取消或删除菜单不删除已建权限

### 场景 5：配置权限树

- **角色**：平台应用管理员
- **前置条件**：应用详情「权限」Tab；只读全量树 `/platform/config/permission`
- **步骤**：创建只选 GROUP / ACTION。GROUP 编码以 `:**` 结尾。去掉托管 / 只读标记。更新不能改编码、节点类型、资源绑定
- **预期结果**：树节点只有 `nodeType`。全量树「类型」列展示节点类型

### 场景 6：角色绑定功能权限与数据范围

- **角色**：平台角色管理员 / 租户通讯录角色管理员
- **前置条件**：平台角色页；组织「角色」「权限」页
- **步骤**：绑权树用 `id` + `nodeType` + `code` 勾选。平台角色编辑数据规则（当前来源层整体替换）。组织角色改为编辑本租户追加层；平台默认规则在租户入口只读提示
- **预期结果**：空列表清空当前层；平台 CUSTOM 不出现租户部门选择；组织页不把平台层与租户层混成一份可编辑列表；组织角色保留「部门角色」`filterDept`

## 功能需求

### REQ-001：有效权限独立接口

系统 SHALL 将 `GET /api/pms/v1/auth/user/permissions` 写入权限 store，并与用户资料、菜单并行 bootstrap。

**验收标准：**

- [x] 登录后只并行打 `info` / `menus` / `permissions` 各一次；路由 `beforeEach` 不重复拉取
- [x] store 保存权限码与 `version` / `generatedAt` / `expiresAt`，不按 `expiresAt` 做 interval
- [x] 按钮与表格操作使用有效具体权限码；不用角色编码作为默认放行；不用菜单权限码
- [x] `v-auth` 权限码精确匹配；角色编码仅作产品态展示

### REQ-002：应用资源目录与默认访问

系统 SHALL 在应用配置中维护默认访问策略与资源目录。

**验收标准：**

- [x] 列表 / 创建 / 详情可读写 `defaultAccessMode`（开放 / 申请制）
- [x] 应用详情有资源 Tab，可查询 / 创建 / 更新 / 删除；更新不可改编码
- [x] 权限表单创建时可绑定 `resourceId`；更新权限不可改资源绑定
- [x] 应用根权限不可删

### REQ-003：菜单可见性改为权限 ID 列表

系统 SHALL 用 `permissionIds` + `permissionMatchMode` 表达受保护菜单的可见条件。

**验收标准：**

- [x] 菜单配置无 Button；受保护页 `permissionIds` 非空且为 ACTION；开放 / 目录页 `permissionIds` 为空
- [x] 菜单表格展示关联权限数量或开放，不再展示单个权限码
- [x] 快捷新建权限默认 `nodeType` 为 ACTION，用返回 ID 加入勾选

### REQ-004：权限节点只认 nodeType

系统 SHALL 按 GROUP / ACTION 维护权限树，不使用旧的 `type` / `managed` / `readOnly`。

**验收标准：**

- [x] 应用权限树与全量树均按 GROUP / ACTION 展示
- [x] 创建必传 `nodeType`；GROUP 编码以 `:**` 结尾
- [x] 去掉托管 / 只读 UI

### REQ-005：角色数据规则按来源层维护

系统 SHALL 让平台入口只写平台默认层，租户入口只写本租户追加层。

**验收标准：**

- [x] 平台角色行操作「数据范围」整体替换当前层；空列表清空
- [x] 组织角色节点菜单「数据范围」只维护租户追加层，并提示不能改平台默认
- [x] 平台入口 `scopeType` 不含 CUSTOM；组织入口含 CUSTOM 且用部门选择
- [x] 组织角色表单删除全局 `scopeType` / `scopes`，保留 `filterDept`
- [x] 绑权 body 仍为权限 ID 列表

### REQ-006：403 / 503 语义可区分

系统 SHALL 把明确无权限与授权快照不可用分开处理，且后者不得把会话清成游客。

**验收标准：**

- [x] HTTP 403 提示无权限并刷新权限，不登出
- [x] 503 `AuthorizationSnapshot.Unavailable` 提示「授权服务暂时不可用，请稍后重试」并刷新权限，不清空权限、不登出

## 非功能需求

- 不从 JWT 解析 RBAC；切组织仍走重新登录
- 窗口重新可见且已过 `expiresAt` 时可静默刷新权限；`version` 变化再拉菜单
- 官方插件不得互相依赖：平台与组织各有一份数据规则抽屉
- `plugins/member` 权限页行为不变

## 依赖与约束

- 接口副本见归档 [API.md](../../../changes/archive/2026/20260911-base-rbac-data-authorization/API.md)
- `DataScopeTypeEnum` 为数字枚举，文案为「全部 / 指定部门 / 本部门及下级 / 本部门 / 仅本人」
- 前端 ID 继续用 `string`，与雪花 ID 的 JSON 字符串一致
- 创建权限接口返回 ID，供菜单快捷新建勾选

## 验收标准

- [x] 登录 bootstrap 只并行打三次；按钮来自有效权限码
- [x] 菜单无 Button；权限树无旧 `type` / 托管 / 只读
- [x] 应用可配默认访问与资源目录
- [x] 平台 / 组织角色可维护各自来源层的 data-rules
- [x] 403 明确无权限；503 提示重试且不登出
- [x] member 权限页未误改
