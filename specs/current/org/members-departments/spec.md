# 成员与部门

本文写已验收的页面行为；部门负责人及详情聚合接口见归档[负责人 API](../../../changes/archive/2026/20261019-org-department-leaders/API.md)，目录与计数见[目录 API](../../../changes/archive/2026/20261017-org-members-dept-tabs/API.md)。成员导出、字段可见性及 capabilities 仍遵循主 IAM 契约。

## 概述

组织管理下「成员与部门」是目录，下面再挂「成员」「部门」两个页面。成员页左侧部门树、右侧成员表；部门页为树形表。账号与成员分离、字段可见性、对象能力和非空删除规则保持不变。成员表格导出提交后到「我的下载」获取文件。

## 范围

### In Scope

- 路由 `org.iam.members`、`org.iam.departments`
- 成员左树筛选、成员表默认列与批量工具栏
- 已移出成员重新加入
- 部门树形表、人数列与批量工具栏
- 普通部门负责人摘要、无 Tab 详情及基本信息/负责人统一编辑
- 旧 `?tab=departments` 深链重定向到部门页

### Out of Scope

- 用户组、组织设置、角色与授权等其他租户页
- 部门状态、独立导入接口（入口可先挂上）
- 岗位、审批、负责人动态授权、部门群或邀请成员

## 用户场景

### 场景 1：按部门查看成员

- **角色**：具备 `iam-tenant:member:read` 的租户管理员或授权成员
- **入口**：组织管理 → 成员与部门 → 成员
- **步骤**：左树搜索并选择部门；按手机号/邮箱/状态筛选；多选后批量变更部门、离职、导入导出；添加、详情、暂停、恢复、移出
- **预期结果**：左栏无部门增删改按钮；表头显示当前部门名与人数

### 场景 2：维护部门树

- **角色**：具备 `iam-tenant:department:read` 的身份
- **入口**：组织管理 → 成员与部门 → 部门
- **步骤**：树形表搜索部门名；新建、添加子部门、打开详情编辑、删除空部门
- **预期结果**：人数来自 `memberCount`，缺失显示 `-`；无读权限时侧栏不出现部门菜单

### 场景 3：已移出成员重新加入

- **角色**：具备 `iam-tenant:member:create`
- **入口**：成员页添加成员，或筛选已移出后的行操作/详情
- **步骤**：提交同一手机号，或打开「重新加入」改姓名、联系方式和部门后提交
- **预期结果**：成员回到在职；提示原有角色和用户组已清除

## 功能需求

### REQ-001：两个独立子页面

系统 SHALL 用两个路由分别承载成员页与部门页，互不挂载对方表格。旧 `?tab=departments` 进入成员页时重定向到部门路由。

### REQ-002：成员左树

成员左树消费 `GET /v1/tenant/departments` 的真实层级，再把直属一级部门提到与根平级，默认选中根部门。选择部门对话框按接口层级展示，默认展开根。选中根部门时成员列表不传 `departmentId`，右侧人数是当前可见的组织成员总数；选中其他部门才按直属任职筛选。根部门显示 24×24 圆角矩形组织 logo，缺失时用部门名首字；根节点不占展开箭头槽。子部门显示组织图标。左树不放新建部门。

### REQ-003：成员表

姓名列固定最前，显示头像与姓名。默认显示姓名、账号状态、手机号、部门、登录手机号；默认隐藏邮箱、入职时间、更新时间。字段不可筛选或不可见时不展示对应筛选项或列值。表头在选中后显示「列名 · 已选 N 条」。

工具栏从左到右为批量操作离职、批量变更部门、批量导入/导出、添加成员。仅添加成员固定直出，其余随宽度收纳。已移出行提供「重新加入」，权限为 `iam-tenant:member:create`；在职行不出现该操作。

### REQ-004：部门表

部门表默认显示部门名称、部门人数、负责人及操作；排序默认隐藏。主部门顶格、无展开槽、无详情或删除、勾选关闭，人数为组织未移出成员总数；子部门缩进后可展开、多选并进入详情，人数为直属 ACTIVE 成员。人数缺失显示 `-`。部门操作按 capabilities 禁用并给出原因。

工具栏顺序为批量删除、批量导入/导出、新建部门，全部固定直出。

### REQ-005：导出

成员表格导出在导入导出页选择范围后立即提交。提交成功关闭范围对话框，并提示可前往「我的下载」。文件保留 7 天，状态和下载见 [我的下载](../../packages/download-center/spec.md)。本页不再轮询或直接下载该文件。导入仍在本页等待结果。

### REQ-006：添加成员

点击「添加成员」打开标题为「添加成员」的对话框。字段为姓名、部门、手机号码、工作邮箱，不提供账号 ID 或登录名查找。手机号前显示 `+86`，前端只校验 11 位数字，号段由后端判断。部门默认带上左树当前部门，允许清空。

提交 `POST /v1/tenant/members`。新建账号时弹出一次性密码对话框；已有在职账号提示「该手机号已有账号，已加入组织」；命中已移出成员提示「该成员已重新加入组织，原有角色和用户组已清除」并刷新列表。一次性密码对话框是 `BizIamAccountSecretDialog`，平台账号页共用。平台创建账号仍按原抽屉，不改为手机号入职。

### REQ-007：负责人摘要与组织事实

部门负责人是独立组织关系，可为零或多位，非空时唯一主负责人。允许有效成员跨部门兼管，不改变任职；任免不授予角色、操作、数据范围或 Token 属性。暂停/移出负责人仍保留关系，标记不可用且不自动换主。

负责人列只使用服务端主负责人投影，展示 30px 头像、姓名及“和其他 X 人”，X 为不含主负责人的人数。仅在主负责人存在、关系完整可见且多人时显示人数；单人只显示姓名，确实未设置为 ASCII `-`。主负责人不可见显示“主负责人受限”，部分关系不可见显示“部分信息受限”且不推断总人数；姓名隐藏与不可用提示保留。

### REQ-008：部门详情与统一编辑

详情没有 Tab 或“更多操作”，顶部为 56px 主题圆底部门图标与部门名称。只读与编辑保持同一字段顺序：部门名称、上级部门、排序、部门负责人。上级显示授权名称而非 ID；父对象不可见时显示受限，不能当作未设置。删除仍通过列表入口并按原权限、空部门及负责人关系约束执行。

详情响应一次提供可见上级名称及负责人首屏；打开抽屉或选人对话框不重复查询该首屏。只读负责人用头像姓名标签，主负责人在已知标签首位并带“部门主负责人”；编辑框使用相同标签，点击进入[组织成员对话框](../../packages/tenant-member-picker/spec.md)。真实头像优先，未设置、受限或加载失败使用已授权姓名后两字及主题色圆底，不补查隐藏资料。只读空值为横杠，编辑空态为选择提示；受限与未加载关系保留提示及差量边界。

基本信息和负责人共用一次编辑会话。按实际变化分别校验 `department:update` 与 `department:leaders`，只具一种权限时仅编辑对应部分。统一保存携带同一 `expectedVersion`，提交变化部分和负责人增删/设主差量；整体成功或失败，成功刷新详情与列表，取消不落库。409 保留两部分草稿并要求重新加载核对，不自动覆盖。

上级部门复用成员部门选择对话框的单选模式，根可展开，当前部门及其子树不可选择，导航骨架不可选择。名称由详情快照回显，不为回显拉完整树；打开时加载既有部门树，确认才修改父表单，取消保持不变。服务端仍校验租户、范围及循环。

### REQ-009：负责人对话框扩展

候选与已绑定关系分页独立。已有负责人由父详情传入完整或部分首屏快照，后续按需追加，不以已加载列表覆盖隐藏/未加载关系。对话框确定仅回填草稿，最终由部门统一保存落库。

从空集合选择首位有效成员自动设为主负责人，其他人可用“设为部门主负责人”切换。主动移除当前主负责人时优先选择已知可用的剩余成员；没有可操作剩余成员则继续加载或明确选择。打开旧关系、翻页或状态变化不会自动替换受限/不可用主负责人。普通人员选择不附带这套主负责人规则。

### REQ-010：已移出成员重新加入

筛选已移出后，行操作与详情「更多操作」提供「重新加入」。对话框预填姓名、明文手机号、未脱敏邮箱和部门；通讯录手机号若被脱敏则不预填，避免把掩码提交回去。提交 `POST /v1/tenant/members/{id}/rejoin`，带 `expectedVersion`。提交前提示旧角色、用户组和负责人关系会被清除，部门以本次提交为准。详情 `GET` 仍排除已移出，已移出详情以列表行资料打开。

## 依赖与约束

依赖后端管理部门树与 `memberCount`。菜单由 IAM 种子生成，已有库走 `023_tenant_members_departments_menus.sql`。带子集的二级目录使用 `layout.simple`。
