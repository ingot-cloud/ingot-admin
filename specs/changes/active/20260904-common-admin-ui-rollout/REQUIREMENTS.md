# 需求：管理台业务页面 UI 迁移

## 场景与页面

### 场景 1：浏览概览页

- **角色**：后台管理员。
- **入口**：Dashboard。
- **步骤**：查看组织摘要、关键指标、待办、趋势和快捷入口。
- **预期结果**：信息按重要度分组，卡片密度统一，数值与时间范围清晰，无纯装饰性重复信息。

### 场景 2：查询和操作列表

- **角色**：后台管理员。
- **入口**：用户、角色、应用、租户、字典、会话等列表页。
- **步骤**：设置筛选、查询、浏览表格、分页、打开详情或新增/编辑入口。
- **预期结果**：页面头、筛选工具栏、表头和分页保持稳定，只有表格数据区滚动；快捷操作、`…` 菜单和字段显示设置一致，原查询条件和权限行为不变。

### 场景 3：使用左树右表页面

- **角色**：组织或权限管理员。
- **入口**：部门、组织用户、组织角色、组织授权、字典等页面。
- **步骤**：在左侧选择树节点或分组，在右侧查询和操作数据。
- **预期结果**：左侧默认 260px，可从分隔线折叠；左右区域独立滚动，选择上下文始终可见，小于 1024px 时左侧以覆盖层呈现。

### 场景 4：维护设置和策略

- **角色**：安全管理员。
- **入口**：访问防护、账号保护、凭证策略、会话策略等页面。
- **步骤**：切换局部 Tab，查看策略，进入编辑态并保存或取消。
- **预期结果**：Tab 层级、分组标题和保存位置统一；未访问 Tab 不发请求；各栏独立保存语义不变。

### 场景 5：完成长表单或危险操作

- **角色**：有写权限的管理员。
- **入口**：新增、编辑、详情抽屉或确认弹窗。
- **步骤**：填写、校验、提交或取消；执行停用、删除、下线等危险操作。
- **预期结果**：抽屉操作区固定，错误定位明确；危险操作显示对象和影响范围，权限及接口语义不变。

## 页面结构

业务页面统一映射到以下原型：

- **Overview**：`InPageFrame page` + 固定页面头 + 可滚动摘要/指标/快捷入口。
- **List**：`InPageFrame contained` + 固定页面头/筛选/操作栏 + 可滚动表格数据区 + 固定分页。
- **Split List**：`InPageFrame contained` + 固定页面头 + 可折叠左树 + 右侧固定工具栏/可滚动表格。通讯录各页为独立菜单路由，不在页面头放置路由 Tab。
- **Settings**：`InPageFrame page` + 固定页面头/局部 Tab + 可滚动信息区块和编辑区。
- **Detail**：`InPageFrame page` + 返回/面包屑 + 固定标题摘要 + 可滚动分组内容。
- **Tool**：`InPageFrame page` + 固定页面头 + 可滚动单一任务区和帮助信息。

## ADDED

### REQ-A001：页面原型一致性

系统 SHALL 将所有在范围内的页面归类到明确原型，并使用 foundation change 提供的共享组件组织页面。

**验收标准：**

- [ ] 每个页面在 DESIGN.md 页面矩阵中有且只有一个主要原型。
- [ ] 同原型页面的标题、说明、筛选、操作、内容和分页顺序一致。
- [ ] 每个页面显式选择 `InPageFrame` 的 page/contained 模式，不在页面根节点重新声明整页滚动。
- [ ] 业务页面不复制顶栏、侧栏或全局面包屑。
- [ ] 不为单页新增与 `admin-core` 重复的基础设计组件。

### REQ-A002：列表与筛选一致性

系统 SHALL 统一列表页的筛选、操作栏、表格、分页和状态反馈，同时保留原请求触发条件。

**验收标准：**

- [ ] 搜索、重置、主要新增操作和次要操作位置在所有列表页一致。
- [ ] 页面头、筛选工具栏、表头和分页按 contained 契约固定，只有表格数据区纵向/横向滚动。
- [ ] 简单选择型筛选可在原业务允许时即时应用；文本或组合筛选仍通过显式查询避免高频请求。
- [ ] 宽表格仅在表格区域横向滚动，操作列和选择列按页面需要固定。
- [ ] 行内最多直接展示“详情”和一个领域高频动作，其余操作进入无文字 `…`；工具栏固定操作保持直出，同组低频/批量操作按容器宽度整体展开或整体进入 `…`。
- [ ] 需要字段显示设置的页面提供稳定 `tableId`，必选列不可隐藏，显示偏好不改变请求或导出语义。
- [ ] 空数据、无结果、错误、无权限和加载态使用共享状态呈现。
- [ ] 分页参数、总数、页大小和刷新语义保持不变。

### REQ-A003：双栏页面一致性

系统 SHALL 统一组织、权限和字典等左树右表页面的宽度、分隔、滚动与窄窗口行为。

**验收标准：**

- [ ] 左栏默认宽度 260px，使用 foundation 的折叠柄、`v-model:left-open` 和页面级持久化键。
- [ ] 左栏选择上下文在右侧标题或摘要中可识别。
- [ ] 左右区域各自承担必要滚动，不产生双重纵向滚动陷阱。
- [ ] 窄窗口中左栏可以抽屉或覆盖层方式打开，主操作保持可达。

### REQ-A004：设置、详情和局部 Tab 一致性

系统 SHALL 统一设置/详情页面的局部 Tab、分组标题、查看态、编辑态和操作区。

**验收标准：**

- [ ] 局部 Tab 不与全局路由 Tab 混淆，切换后保持原懒挂载和 URL query 行为。
- [ ] 页面内可安全编辑的设置优先原位编辑；长实体编辑继续使用抽屉。
- [ ] 保存和取消操作在长页面中始终可见或可快速到达。
- [ ] 信息分组使用标题、说明和细分割线，不依赖强阴影或装饰性蓝条。

### REQ-A005：操作反馈与危险行为一致性

系统 SHALL 统一保存、删除、停用、强制下线等操作的 loading、确认、成功和失败反馈。

**验收标准：**

- [ ] 提交期间主操作显示 loading 并阻止重复提交。
- [ ] 危险确认包含动作、对象名称或标识以及可理解的影响说明。
- [ ] 成功后沿用原 Query 失效或刷新范围，不执行整页无差别刷新。
- [ ] 原有“数秒内生效”“下次登录生效”等业务提示不得丢失。
- [ ] 无写权限页面保持只读，不能仅将按钮置灰后仍可触发。

### REQ-A006：响应式与可访问性

系统 SHALL 在 foundation 定义的主要桌面尺寸和窄窗口下保证业务页面功能可达。

**验收标准：**

- [ ] 1440×900、1280×800、1024×768 下完成全部页面视觉检查。
- [ ] 代表性 List/Split List 使用至少 200 行 fixture 验证固定页面头、独立数据滚动和固定分页。
- [ ] 小于 1024px 时筛选、树栏和表格可降级，但不存在被永久隐藏的关键操作。
- [ ] 表单标签、必填、错误、禁用和只读状态不只依赖颜色。
- [ ] 所有图标操作具有 Tooltip 或可访问名称，键盘焦点顺序合理。

### REQ-A007：业务行为零回归

系统 SHALL 把本 change 视为呈现层迁移，除本需求明确约定外不改变业务行为。

**验收标准：**

- [ ] 25 个页面入口、路由 path、canonical viewPath 和菜单权限不变。
- [ ] 查询条件、API、分页、枚举、缓存失效和写操作参数不变。
- [ ] 安全域未访问 Tab 不发请求、独立保存、字符串 ID 等既有约束继续通过测试。
- [ ] 页面迁移前后的关键业务路径形成可复查回归清单。

### REQ-A008：操作分层与字段偏好迁移

系统 SHALL 将现有列表操作和列显示能力映射到 foundation 的 `InTableActions` 与 `InColumnSetting`，不在业务页面维护同义通用实现。

**验收标准：**

- [ ] 页面在 `table.ts` 或明确的展示配置中标记详情、高频、普通、危险、必选列和可配置列。
- [ ] 权限、禁用条件、危险确认文案和 handler 来自页面/`useOps.ts`，共享组件不直接调用业务 API。
- [ ] 无选择时依赖批量上下文的操作不可触发，并提供可理解的禁用原因。
- [ ] `org/contacts/user` 试点中邀请/添加始终直出；批量导入/导出、批量变更部门、批量操作离职整组展开或收纳，不出现部分展开中间态。
- [ ] `…` 菜单支持键盘打开、方向键选择、Esc 关闭和焦点返回；纯图标按钮具备可访问名称。
- [ ] 字段显示偏好只影响当前表格呈现，不影响后端查询、批量导出、权限检查和缓存失效。

## MODIFIED

### REQ-M001：访问防护页面呈现

**原规格：** `current/security/access-protection/spec.md`。

**变更说明：** 保持单页多 Tab、挑战策略 CRUD 和热更新提示不变，迁移到统一 Settings/List/Drawer 视觉结构。

**验收标准：**

- [ ] 未访问 Tab 不发请求。
- [ ] 挑战策略的路径/分组互斥、字符串 ID 和 `/vc` 校验不变。
- [ ] 新建、编辑、删除入口符合统一操作反馈规范。

### REQ-M002：账号保护页面呈现

**原规格：** `current/security/account-protection/spec.md`。

**变更说明：** 保持账号锁定 Tab 和 B/C 两栏独立保存，统一局部 Tab、双栏策略卡片和页面内编辑态。

**验收标准：**

- [ ] B/C 两栏不合并提交。
- [ ] 永久锁定仅 B 端可用，无权限时保持只读。
- [ ] 两栏在 1024px 下可读，在更窄窗口按单列排列。

### REQ-M003：会话管理页面呈现

**原规格：** `current/security/session-management/spec.md`。

**变更说明：** 保持在线会话与并发策略两个 Tab 的查询和写操作语义，统一筛选、表格、详情抽屉和危险确认。

**验收标准：**

- [ ] 未满足 clientId/userId 查询条件时仍不请求。
- [ ] 下线绑定 `sid`，详情与并发策略行为不变。
- [ ] GLOBAL 策略不可删除，`maxSessions=0` 仍显示“不限制”。

## REMOVED

无业务功能移除。迁移过程中仅移除被 foundation 共享能力替代的重复基础样式和页面级通用布局实现。
