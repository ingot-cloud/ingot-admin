# 性能验证设计（draft）

本设计承接既定门槛，具体执行方案待目标输入齐备后评审。Auth权威事务、Gateway与资源认证、BFF交付/恢复、IAM读取及Redis派生链路按实际跳数测量，不用模拟返回代替服务端工作。

## 输入与方法

先登记目标CPU/内存、磁盘与持久性、三节点GR/Router、网络、连接池、峰值QPS/业务比例、并发与突发、运行时长/预热/采样及版本。建立同资源基线，再分场景执行峰值/2倍突发、RT集中、冷缓存与outbox积压，保留失败率、延迟分布、DB/池/GC与积压恢复证据。尚未确认的输入不写成既成事实，不启动有中断风险的目标环境负载。

## 安全/接口/迁移/兼容

不改变现有R<T>/时间/错误码、Cookie及token期限，不新增公开grant或放宽身份校验；默认无DDL或协议改动。若优化需要索引、池配置或其他行为变化，先补设计、兼容与迁移/回滚评审。仅回退ledger-compatible版本，不恢复已撤销身份，不回退Redis权威。任何安全断言失败即停止达标计数并保留证据。

## 工件和边界

保存输入清单、精确包/配置摘要、命令、原始测量出处、脱敏统计、失败重跑与清理。主变更F12可在功能安全范围收口，性能门禁依然由本change阻断发布。三VM同宿主功能验收不是目标性能或物理容灾验收。

前端仅承接端到端操作延迟和页面可用性/错误反馈，不向apps或插件反向引入公共逻辑，符合既有宪章。当前仅文档拆分，不改运行配置或代码。
