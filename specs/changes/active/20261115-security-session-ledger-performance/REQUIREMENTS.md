# 性能需求与验收

## 承接范围

继承主变更已批准的L07-P，不降低门槛：

- 权威认证P95≤15ms、P99≤50ms。
- 组织切换P95≤500ms、P99≤1s。
- 同资源条件吞吐达到原基线90%以上；数据库CPU与连接池保留至少30%余量。
- 验证峰值、2倍突发、集中RT刷新、冷缓存及outbox积压，观测端到端链路和各跳耗时。
- 目标机器/存储/网络/数据库拓扑、基线版本、峰值QPS及压测时长须先确认；当前未提供，不能用三台功能VM臆定生产目标。

## 安全与真实性

全程保留权威账本、GR一致性屏障、durability、凭据代次、注销/RT撤销与原截止。不得引入JWT-only、正向身份缓存、旧副本认证或弱化持久性换取性能。延迟统计包含失败/超时及错误率，不从样本剔除慢请求；分场景记录P50/P95/P99、吞吐、资源与恢复曲线。

若需要优化业务行为、数据模型、接口或部署，先形成并确认设计修订，再实施。每次变更保留正确性/安全回归；功能证据不替代性能证据。

## 通过与发布

最终协调包在已确认目标环境和负载下全部门槛通过，证据/基线/制品摘要可重现，完成资源清理及发布方确认后才解除本门禁；部分通过、环境不符或仅报告优化比例均不算通过。本轮保持未通过及发布阻断。
