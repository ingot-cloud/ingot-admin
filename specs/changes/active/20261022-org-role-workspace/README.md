# 组织角色与授权工作区

> 状态：implementing

## 协作模式

一人全栈

## 背景与动机

组织「权限与应用 / 角色与授权」仍是角色表加编码表单。平台「角色与授权」已是左角色、右成员/用户组，权限用同一套选择、范围和预览。租户角色没有业务版本，界面也不展示角色编码。

## 目标

角色 Tab 对齐平台工作区交互。权限和范围沿用相同步骤。名称、说明和来源用中文表达。编码只在创建时生成并入库，页面不采集、不回显。

## 范围

### In Scope

- 左角色列表、右成员/用户组、来源对话框
- 创建向导与详情抽屉：无编码、无版本
- 权限选择、范围、字段权限、预览；共享角色只读
- 字段步骤放在 admin-common，租户角色与平台共享角色立即生效
- 「授权记录」改名「角色分配」，授权管理员保留，列表样式对齐平台，去掉版本列
- 分配角色改为与平台相同的四步全屏向导：多接收对象、多角色、共用有效期、按角色配置范围、预览后保存
- 权限诊断降为次要入口，表单改用成员、应用、操作、目标对象候选选择器

### Out of Scope

- 版本筛选、版本历史、升级
- 插件互相引用
- 通讯录字段策略
- 提前改 `specs/current/`

## 风险与依赖

右侧成员和来源依赖新增的租户角色工作区接口。无该接口时不能用角色列表回查拼成员。

诊断选择器依赖后端新增的 `GET /v1/tenant/authorization/diagnose/candidates`。
