## 背景与动机

现有顶栏已有品牌、搜索开关和主题插槽，但缺少统一的 APP 配置入口。品牌标题未跟随侧栏收起，一级入口缺少宽度驱动的溢出收纳，功能小部件与用户入口混在同一区域，用户菜单固定，限制了不同 APP 的组合能力。

## 目标

将默认顶栏划分为品牌、大类菜单、搜索、功能小部件、用户入口五区。APP 配置内容与业务动作，admin-core 提供共享布局、默认功能、分组浮层及响应式收纳。

## 范围

### In Scope

- APP 顶栏配置及公开 TypeScript 类型、主题读取能力。
- 品牌与侧栏宽度、收起状态联动。
- 大类入口、受控选中态、点击回调、分组面板及溢出收纳。
- 搜索显隐兼容、紧凑入口和自定义搜索组件。
- 内置与 APP 自定义小部件的配置、排序、动态显隐和收纳。
- 用户入口展示、内置菜单选择/排序/隐藏、自定义菜单扩展。
- 配置示例、文档、自动化及浏览器验证。

### Out of Scope

- 大类与侧栏的业务分组、系统切换、路由恢复及业务内容联动。
- 后端接口、全局搜索服务、消息业务、语言切换或账号切换业务实现。
- 运行时主题切换、全局路由标签栏、其他在途变更。

## 风险与依赖

- 动态宽度、自定义组件及侧栏动画需要真实浏览器验证，单元测试不能替代布局验收。
- 自定义主题通过公开配置读取能力按需接入；不会强制重排已有自定义 header。
- 保留现有主题插槽和默认行为；不得把组件、回调存入持久化配置。
- 当前全局路由标签栏拆除 change 为 validating；本变更不修改其规格或重新引入已移除能力。
