# 平台“角色”单选树增量（2026-09-29）

状态：validating（开发完成，待用户手动验收）。批准依据：jy 确认单选角色版本，并明确要求实施本会话计划。

## 需求、设计与接口

“角色版本”字段改为“角色”，点击打开单栏对话框，不显示右侧已选列表。沿用成员弹窗的搜索、间距、按钮和主题 Token。两级树固定为角色名称 → 已发布版本；角色只展开，版本单选，不默认最新版。搜索在弹窗内按角色名称进行，300ms 防抖；确定更新抽屉，取消保留原选择，字段显示角色名称 · v版本号。

新增后端 GET `/api/iam/v1/platform/assignments/role-candidates`，参数 `delegationGrantId?`、`roleId?`、`keyword?`、`ids?`、`page=1`、`pageSize=20`。不传 roleId 查询角色，传入后查询其可分配版本；版本倒序。响应分页 `items,total,page,pageSize`，节点提供 id、roleId、roleName、name、nodeType（ROLE/REVISION），版本额外提供 revisionNumber、roleRevisionRef。

树数据由后端提供，按单条委派过滤；不解析名称、不使用通用角色列表。根及子节点分别分页，展开才加载版本，版本有“加载更多版本”。已选少量节点按 ID 回显，未加载页不丢失选择。确认时使用现有 ROLE_REVISION 候选按版本 ID 获取完整参数，并再次验证可用性。

弹窗内相同请求合并复用，关闭/依据/权限变化清缓存并忽略迟到响应。失败提供重试，确认防重复。同一版本保留范围参数，不同版本重建参数并使预览失效；已保存分配角色仍只读。共享组件放 admin-common，平台插件注入 API，符合宪章分层与类型约束。提交和预览契约、数据库不变。

测试前由用户重新构建并重启 IAM，加载新控制器；前端加载最新公共包与平台插件。按以下步骤手动验证：

1. 分配角色抽屉显示“角色”，打开后为单栏；角色只展开，版本只有一个可选值，取消不修改原选择，确定回显角色名称 · vN。
2. Network：打开首次只取根角色，展开只取当前角色版本，确认才调用旧 candidates 的 kind=ROLE_REVISION&ids=单版本；页面不请求通用角色列表或全部版本。
3. 搜索角色、清空搜索、角色超过 20 条翻页；单角色超过 20 个版本加载更多。版本按版本号倒序，同名角色按真实角色 ID 分离。
4. 选择旧版本后关闭再打开；根角色/版本不在第一页时仅按少量 ID 回显，仍保留选中状态，不拉取全集。
5. 填写范围参数并预览，再次确认同一版本，参数保留；更换版本，参数重建且预览失效。成员和用户组共用已选版本，编辑已保存分配不能更换角色。
6. 纯受限管理员仅看到所选委派允许的角色版本；手工替换 roleId/ids 或使用他人、撤销、到期的委派，不能获得越界候选。版本/角色/计数与回显边界一致。
7. 开启慢网络，快速输入/翻页/关闭重开，不被旧响应覆盖。重复点击确认不重复取数；503 或断网显示重试，403 刷新资格，已失效版本不能确认。
