# 需求：组织用户组左右栏

## 场景与页面

### 场景 1：左组右人

- **角色**：具有 `iam-tenant:group:read` 的组织管理员
- **入口**：组织管理 → 用户组 `/org/iam/groups`
- **步骤**：进入页面。已有用户组时默认选中第一条；也可以再点左侧其他组
- **预期结果**：右侧列出选中组的有效成员，标题为组名和「共 N 人」

### 场景 2：部门加人后自动出现

- **角色**：同上
- **入口**：已配置部门来源的组
- **步骤**：把成员加入该部门（或含下级时的子部门），回到用户组刷新右侧
- **预期结果**：该人出现在有效成员中，来源为部门名或「部门名（含下级）」；不能行内移出

### 场景 3：工作区直接添加 / 移出

- **角色**：具有 `iam-tenant:group:update` 且对象允许
- **步骤**：添加走组织选人对话框；移出只对「直接添加」出现
- **预期结果**：只改直接成员，部门来源不变，不预览。两种来源都有时，移出确认说明仍会因部门留在组内

### 场景 4：创建 / 编辑范围

- **角色**：create / update
- **步骤**：新建，或从详情抽屉点「编辑」，进入分步向导：基本信息、成员与部门来源（含下级）、检查并保存。详情本身只读
- **预期结果**：创建可直接完成；编辑名称、成员或部门范围须预览通过。删除被引用组不能静默撤权

### 页面结构

- 左 240px 可折叠组列表：搜索、选中、分页、新建、详情/删除
- 右表：姓名、账号状态、手机号、部门、来源、移出
- 详情只读，小节样式对齐飞书基本信息：名称、说明、来源。来源列出部门名称（含下级），有直接成员时追加「直接添加」，不展示部门 ID 和有效人数。删除为图标加文字，编辑仍是主按钮

## 验收标准

- [ ] 布局为左组右人，不引用 platform 插件
- [ ] 进入页面时若当前页已有用户组且尚未选中，默认选中第一条
- [ ] 右侧是有效成员，部门加人后刷新可见
- [ ] 仅部门来源无移出；直接添加可移出且保留部门范围
- [ ] 添加成员走组织选人，已选栏用直接成员接口
- [ ] 创建与编辑走分步向导，详情为抽屉；编辑须预览通过
