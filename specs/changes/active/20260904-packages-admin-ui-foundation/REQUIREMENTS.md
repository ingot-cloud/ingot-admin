# 需求：管理台 UI 基础设施

## 场景与页面

### 场景 1：使用统一管理台框架

- **角色**：后台管理员。
- **入口**：任意使用 `layout.main` 的管理台页面。
- **步骤**：进入管理台，使用顶栏、侧栏、面包屑和页面内容区完成导航。
- **预期结果**：框架在不同页面保持统一尺寸与层级；全局顶栏、面包屑和页面头固定，页面正文、双栏和宽表格按原型独立滚动。

### 场景 2：展开与收起侧栏

- **角色**：后台管理员。
- **入口**：主布局左侧导航。
- **步骤**：滚动长菜单，展开或收起导航，再刷新或继续访问其它页面。
- **预期结果**：展开宽度为 236px，收起宽度为 52px，动画约 300ms；菜单内容可独立滚动，“收起导航”固定在底部且不随菜单移动，选择状态可持久化。

### 场景 3：使用共享列表与筛选组件

- **角色**：业务页面开发者和后台管理员。
- **入口**：使用 `InSplitLayout` 与 `InTable` 的列表页。
- **步骤**：填写筛选条件、执行查询、使用按需表格工具、浏览宽表格、设置列和分页。
- **预期结果**：左栏折叠、工具区、表头、紧凑行高、字段显示设置、空态和分页一致；宽表格仅在表格数据区域滚动。

### 场景 3A：使用左侧筛选栏

- **角色**：组织、权限或字典管理员。
- **入口**：成员、部门、授权、组织用户、字典等左右分栏页面。
- **步骤**：在左侧树或分组中选择上下文，收起或展开筛选栏，在右侧查询和操作数据。
- **预期结果**：左侧默认 260px，可从分隔线折叠；左右区域分别滚动，右侧工具栏、表头和分页保持稳定。

### 场景 3B：使用列表操作和字段设置

- **角色**：后台管理员。
- **入口**：任意使用 `InTable` 的列表页。
- **步骤**：打开行内或批量“更多”菜单，执行详情/高频操作，按需显示或隐藏字段。
- **预期结果**：固定主操作始终显示；可收纳的同组操作在空间不足时整体进入 `…`，空间恢复后整组展开，不出现只展示组内一部分按钮的中间态；字段设置作为按需工具按钮使用。

### 场景 4：编辑实体或设置

- **角色**：后台管理员。
- **入口**：使用 `InDrawer`、`InDialog` 或页面内编辑态的功能。
- **步骤**：打开编辑界面、校验表单、取消或保存。
- **预期结果**：长任务使用抽屉，短确认使用弹窗；操作区固定可见，键盘焦点和关闭行为明确。

### 场景 5：在不同窗口宽度下工作

- **角色**：后台管理员。
- **入口**：桌面浏览器或窄窗口。
- **步骤**：在 1440、1280、1024 和小于 1024px 宽度下访问管理台。
- **预期结果**：桌面信息密度稳定；窄窗口采用折叠或覆盖式导航；内容不会被框架级 `overflow-x-hidden` 截断。

## 页面结构

```text
MainLayout
├── GlobalHeader (56px)
│   ├── Brand
│   ├── Existing menu search
│   └── Existing utilities / User menu
└── Workspace
    ├── SideNavigation
    │   ├── MenuScrollViewport
    │   └── NavigationControl (fixed at bottom)
    └── ContentViewport
        └── InSplitLayout (height: 100%)
            ├── Header (fixed)
            └── SplitBody (min-height: 0)
                ├── LeftPane (260px / 0px, independently scrollable)
                ├── CollapseHandle
                └── RightPane
                    ├── TableTitle / Summary
                    ├── ToolsStart / ResponsiveActions
                    ├── TableDataViewport
                    └── Pagination
```

## ADDED

### REQ-A001：语义化设计 Token

系统 SHALL 在 `@ingot/admin-core` 提供颜色、排版、间距、圆角、阴影、层级、动效和组件尺寸 Token，并由 Ingot Token 单向映射 Element Plus 变量。

**验收标准：**

- [ ] 颜色至少覆盖 `primary #3370ff`、主文字 `#1f2329`、次级文字 `#646a73`、弱文字 `#8f959e`、页面背景 `#f5f5f5`、弱背景 `#f2f3f5`、边框 `#dee0e3`。
- [ ] 间距采用 4px 基线，提供 4 / 8 / 12 / 16 / 20 / 24 / 32px 语义层级。
- [ ] 控件圆角默认 6px，内容卡片使用 8px 或 12px 的明确语义 Token。
- [ ] 页面和组件不得新增与 Token 重复的硬编码品牌色、文字色、表头色或阴影。
- [ ] 明暗主题从同一语义 Token 集派生，不在业务页面维护主题分支。

### REQ-A002：中性全局顶栏

系统 SHALL 将主布局顶栏统一为 56px 白色中性顶栏，品牌主色只用于操作与状态，不使用整块高饱和背景。

**验收标准：**

- [ ] 顶栏高度 56px、白底、默认无阴影；可用画布色差或最多 1px 中性分隔表达层级。
- [ ] 顶栏从左到右为品牌(A)、一级入口(B)、搜索(C)、操作(D) 四区；A/B/D 按内容宽度站位，B/D 分别限制最大 `560px` / `360px`，没有入口时不占空白；C 为 `flex: 1`，搜索默认靠右贴住 D。
- [ ] 现有 Logo、菜单搜索、全屏、设置和用户菜单能力保持可用；窄窗口隐藏 B 区并收缩搜索框。
- [ ] 图标按钮点击区域不小于 32px，并提供 Tooltip、hover、active 与 focus-visible 状态。

### REQ-A003：可收起分组侧栏

系统 SHALL 提供 236px 展开态与 52px 收起态侧栏，菜单信息架构沿用现有静态与动态菜单，不改变路由语义。

**验收标准：**

- [ ] 侧栏面板宽度为 236px / 52px；计入左侧 8px 画布沟槽后，主内容偏移为 244px / 60px。
- [ ] 侧栏背景与页面画布均为 `#f5f5f5`，不得复用白色内容工作面背景，也不使用常驻右边框分隔。
- [ ] 菜单滚动视口从侧栏顶部开始并独占剩余高度；菜单内容顶部留 12px，菜单项高度 40px、相邻项垂直间隔 2px、圆角 8px。
- [ ] 菜单默认 14/20px、400；带图标文字 `#646a73`，无图标文字 `#1f2329`。一级文字与图标列对齐（距面板左侧 44px），无图标子级与上级文字对齐，再下级缩进 20px；超长文案单行省略。
- [ ] 普通 hover 背景为 `rgba(31, 35, 41, 0.06)`；活动背景为 `rgba(31, 35, 41, 0.05)`，活动文字使用 `#2b2f36`、500，只作用在当前叶子，不依赖整行品牌蓝高亮。
- [ ] 展开/收起动画为 300ms，曲线 `cubic-bezier(0.25, 0.1, 0.05, 1)`；外层占位和面板宽度同步变化，并遵守 `prefers-reduced-motion`。
- [ ] 收起态只显示一级 20px 图标和当前一级活动背景；标签、徽标、展开箭头及子级列表不得残留或挤出 52px 面板。
- [ ] 收起态点击带子级的分组图标不临时展开整个侧栏，也不自动弹出二级抽屉；管理员通过底部固定控制恢复完整导航。可点击的一级叶子菜单仍保持原路由语义。
- [ ] 菜单滚动视口与底部控制必须是兄弟区域；只有菜单视口设置纵向滚动，底部控制不得放入 `ElScrollbar`，不得通过 sticky 偶然固定。菜单滚动条不可见，内容仍可滚动。
- [ ] 底部控制高 44px、距侧栏底部 8px，菜单滚动视口与控制区之间保留 18px；展开态文案必须为“收起导航”，收起态只显示反向图标并提供“展开导航”可访问名称。
- [ ] 底部控制使用 20px 图标和 14/20px、400、`#646a73` 文案；默认透明，hover 背景 `rgba(31, 35, 41, 0.08)`、圆角 6px；控制区上方保留 1px `#dee0e3` 分隔线，线与收起按钮间隔 8px。
- [ ] 侧栏菜单项与底部控制文案不可拖选复制。
- [ ] 菜单内容滚动任意距离后，底部控制的 y 坐标、距底部 8px 的间距及焦点位置保持不变；组织/租户信息不占用侧栏菜单头。
- [ ] 折叠控制支持 Enter、Space 和 `focus-visible`；纯图标收起态提供 `aria-label`，不得只依赖图标形状表达状态。

### REQ-A004：统一页面层级

系统 SHALL 统一面包屑、页面标题、说明、操作区、局部 Tab 和内容区块的顺序与间距。

**验收标准：**

- [ ] 页面标题使用 20/28px、600；区块标题使用 16/24px、500；正文默认 14/22px。
- [ ] 面包屑区域约 46px 并保持固定；页面头约 80px、白底、底部中性分隔并保持固定。
- [ ] 侧栏面板左侧窗口沟槽为 8px；侧栏面板与内容工作面之间、以及内容左右使用 `--in-page-gutter`（12px）。面包屑未实际渲染（开关关闭或仅一层）时，内容顶部使用同一沟槽，与左侧对齐。
- [ ] 无版权时壳层不预留下方灰色条，contained 列表工作面贴视口底；页面滚动滑到尽头时，内容底部补与 top/right 相同的沟槽。有版权时内容区整体上移，间距规则不变。
- [ ] 列表和双栏原型默认使用全高白色工作面，不套外层圆角卡片。`InContainer` 默认 `plain` 为透明无边框，允许覆盖背景色、边框色和圆角；信息卡片才使用 8px/12px 圆角和可选边框。
- [ ] 内容区块内边距根据密度使用 16px 或 20px。
- [ ] 面包屑为辅助导航，不与页面标题重复制造两层强标题。
- [ ] 页内 Tab 与全局路由 Tab 视觉和语义分离；默认配置继续允许关闭全局路由 Tab。

### REQ-A005：统一列表、筛选与表格

系统 SHALL 统一筛选区、操作栏、表格、分页、空态和加载态，并由表格自身承担横向滚动。

**验收标准：**

- [ ] 输入框和常规按钮默认高度 32px、圆角 6px；小按钮高度 28px。
- [ ] 成员式紧凑列表表头高度 48px、背景 `#f2f3f5`、文字 `#3f4f66`；数据行高度 44px、底部分隔线 `#dee0e3`。
- [ ] `InTable` 不再内置刷新按钮，也不默认插入字段设置；表格工具通过按需组件和 tools 插槽组合。
- [ ] 为保持现有页面模板可编译，`refresh` emit 声明可保留一个迁移期并标记废弃，但 `InTable` 内部不得再提供按钮或自动触发入口。
- [ ] 标题/摘要、工具栏、表格和分页垂直间距使用 20px；工具项之间默认 12px。
- [ ] 表格数据区由内部 `ElTable` 承担纵向/横向滚动，页面上只出现一条表格滚动条；表头由表格 header 固定，分页固定在表格底部右侧。`.hidden-columns` 不得露出单元格内容。
- [ ] 操作列按需固定在右侧，横向滚动时使用轻量分隔阴影，不由页面根节点截断宽表格。
- [ ] 空数据、无搜索结果、加载失败和无权限具有可区分反馈。
- [ ] 分页位置和上下间距在所有列表页一致。

### REQ-A006：成员式可折叠筛选容器

系统 SHALL 让 `InSplitLayout` 支持飞书成员页式的固定 header、260px 左侧筛选栏、分隔线折叠按钮和右侧全高内容区。

**验收标准：**

- [ ] 容器根使用 `height: 100%; min-height: 0; overflow: hidden`；header 固定，下面的 SplitBody 占满剩余高度。
- [ ] header 为白底、底部分隔，成员页参考高度 79px、内边距 12px 20px；现有 header 插槽保持兼容。
- [ ] 左栏展开宽度 260px、默认背景与容器一致，收起宽度为 0；右侧从 940px 扩展到完整 1200px 时不重建业务内容。
- [ ] 使用层可通过 `left-background` 单独覆盖左栏背景，不传时不得出现与容器不同的默认底色。
- [ ] 折叠按钮尺寸约 16×32px，位于分隔线垂直中点，以无左边框的右侧圆角标签贴齐分割线向右伸出；白底、上/右/下 `#dee0e3`，展开/收起复用同一 12px 箭头并翻转方向。
- [ ] 收起后「展开筛选」按钮仍贴齐工作区左缘，不得变成悬浮在内容里的独立方块。
- [ ] 左栏内容默认 16px 内边距，子组件不得贴住或超出右侧分隔线。
- [ ] 折叠按钮使用原生 button，提供“收起筛选/展开筛选”可访问名称、hover、focus-visible、Enter 与 Space 行为。
- [ ] 左栏和右侧数据区独立滚动；容器可用宽度不足以同时容纳 260px 左栏与最小右栏时自动收起，但不得覆盖用户的桌面展开偏好。
- [ ] 手动展开/收起通过 `v-model:left-open` 控制；`left-collapsible` 沿用当前默认开启，页面显式关闭时不得出现折叠按钮，既有 `persistence-key` 行为保持兼容。

### REQ-A007：按需表格工具与自适应操作收纳

系统 SHALL 让 `InTable` 只负责工具区布局，并通过按需工具组件和自适应 action 组件承载字段设置与业务操作。

**验收标准：**

- [ ] `InTable` 提供 `tools-start` 与 `tools-end` 插槽；旧 `toolbar` 插槽在兼容期映射到 `tools-start`。
- [ ] 字段设置改为完整 32px 按钮组件，由页面按需导入并放入 tools，不再由 `InTable` 自动渲染。
- [ ] `InTableActions` 的 toolbar 变体使用 `ResizeObserver` 监听自身可用宽度；`overflow: never` 操作保持直出，相同 `overflowGroup` 的 `auto` 操作必须整体展开或整体收入 `…`。
- [ ] 空间恢复且能容纳整个折叠组后，该组一次性全部重新显示；`…` 仅在至少有一个折叠组或 `always` 操作时出现，计算宽度时预留其 32px 和相邻 gap。
- [ ] action 配置保留现有 `key`、`label`、`kind`、`permission`、`group`、`confirm`、`disabled`、`disabledReason` 与 `onSelect`，新增 `icon`、`priority`、`overflow` 和 `overflowGroup`；quick 主操作默认 `overflow: never`。
- [ ] row 变体继续遵守“详情 + 至多一个高频快捷操作 + …”，不因操作列变宽而展开全部低频项。
- [ ] 成员页式 toolbar 的“邀请成员”“添加成员”始终直出；三个批量操作同组收纳，展开态为 3 个批量按钮 + 2 个固定按钮，收纳态为“…” + 2 个固定按钮。
- [ ] 收起或展开 `InSplitLayout` 左栏后，工具栏必须随 ToolsEnd 的实际宽度自动重新计算，无需页面手动 refresh/resize，且动画结束后不得抖动。
- [ ] 成员页式批量菜单依次显示“批量导入/导出”“批量变更部门”“批量操作离职”；未选成员时后两项可见但禁用。
- [ ] 为防止 VNode 状态、焦点和 Popover 被复制或移动，只有配置型 action 自动收纳；复杂自定义工具必须放在 tools 插槽并自行提供窄宽度方案。
- [ ] `InColumnSetting` 使用约 213×426px 的普通复选列表；提供“全部”半选、必选列禁用、即时生效、Esc/点击外部关闭和焦点返回。
- [ ] 字段显示状态通过必填 `tableId` 按用户持久化；不新增后端接口，选择列和操作列默认不可隐藏。

### REQ-A008：统一抽屉与弹窗

系统 SHALL 以任务复杂度区分抽屉、弹窗和页面内编辑，并统一标题、内容、操作区和关闭行为。

**验收标准：**

- [ ] 抽屉标题采用中性标题层级，不使用装饰性蓝色竖条作为必需识别元素。
- [ ] 抽屉操作区固定可见，使用顶部边框或轻量背景，不使用重阴影分隔。
- [ ] 弹窗适用于短确认和小型输入；长表单不得默认塞入小弹窗。
- [ ] 关闭按钮、取消、保存的键盘顺序可预测；提交期间防止重复提交。
- [ ] 危险操作组件能承载对象名称、影响说明和危险色主操作。

### REQ-A009：响应式、可访问性与状态反馈

系统 SHALL 在主要桌面尺寸和窄窗口中保持功能可达，并满足基本键盘与对比度要求。

**验收标准：**

- [ ] 在 1440×900、1280×800、1024×768 下无框架级内容遮挡。
- [ ] 使用至少 200 行数据验证 `InSplitLayout` header、表格工具栏、表头和分页固定，左右与表格数据区滚动边界正确。
- [ ] 通过改变组件容器宽度验证 action 自动收纳和恢复，不以浏览器 viewport 断点代替容器测量。
- [ ] 小于 1024px 时侧栏可覆盖式打开/关闭，主内容宽度不被固定侧栏挤压。
- [ ] 在 1280×500 或等效短视口制造长菜单滚动，验证菜单视口发生滚动而底部“收起导航”控制的坐标不变。
- [ ] 可交互元素具备清晰 `focus-visible`；纯图标控件有可访问名称。
- [ ] 正文与背景对比度达到 WCAG AA；状态不只通过颜色表达。
- [ ] 加载优先使用局部 loading 或骨架屏，不用无差别全页遮罩。
- [ ] 动效遵守减少动效偏好。
