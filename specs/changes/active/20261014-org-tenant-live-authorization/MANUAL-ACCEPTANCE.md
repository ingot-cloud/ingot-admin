# 租户授权人工验收清单

日期：2026-10-17。适用于当前未上线测试环境。按下列顺序逐项操作，确认实际结果后再勾选；拥有者转交放在最后，避免影响前面的配置资格。

## 开始前准备

- [ ] 已执行 [一键测试准备脚本](../../../../../ingot/databases/iam/dev/prepare_tenant_live_test.sql)，返回 `TENANT_LIVE_TEST_READY`。已完成则无需重复执行021、022或迁移工具。
- [ ] 已编译并启动新版IAM、相关授权消费服务和两个管理台，浏览器加载的是新前端。
- [ ] 测试账号均有效，首次登录要求修改密码的账号已完成改密。
- [ ] 已保留一份平台原有功能的测试记录，便于最后对照回归。

准备下列身份，名称可以自行替换。不同身份使用不同浏览器配置或独立会话，确保没有误用另一账号。

| 身份 | 用途 |
|---|---|
| 平台管理员P | 创建组织、配置应用、维护共享角色；与组织A拥有者使用不同账号 |
| 组织A拥有者OA | 管理组织A和创建私有角色 |
| 组织B拥有者OB | 验证共享同步及跨组织隔离 |
| 普通成员MA、MB | 分别属于组织A、B，用来验证角色权限 |
| 授权管理员DA | 组织A成员，只通过委派获得分配资格，不另配治理角色 |
| 接收成员RA | 组织A成员，验证范围和委派，最后作为新拥有者 |

组织A准备“研发”“研发子部门”“营销”三个部门，并在各部门放入测试成员；另建测试用户组G。范围测试时，目录可见策略先设为组织内可见，再单独验证角色范围。每组测试开始前，核对接收人是否还有其他直接或用户组授权：其他有效来源仍可提供权限，不能误判为撤权失败。

**判定时点：** 角色权限提交后，本会话下一次业务请求应按新权限判定；其他在线窗口不轮询，重新可见且快照已过期时再核对菜单和按钮，无需重新登录。

## 拥有者与组织初始化

### 01 创建组织并指定拥有者

操作：P创建组织A，所有者选择OA；以OA登录租户端，打开“组织设置”和“授权管理”。再创建组织B并指定OB。

- [ ] 显示的拥有者是创建时指定的人；P不会因创建组织而自动成为该组织拥有者。
- [ ] OA无需分配普通角色，就能管理本组织有效开通的应用。
- [ ] 不自动创建管理员、子管理员、主管等私有角色；拥有者不是可分配的普通角色。

### 02 拥有者动态获得新权限

操作：先确认OA不能访问未开通的测试应用；P为组织A开通该应用。通过平台或服务目录同步，为已开通的测试应用登记一个新启用操作，再由OA发起对应请求。

- [ ] 开通后OA自动获得应用及其权限；新操作无需重新分配角色或升级。
- [ ] 普通成员没有对应角色授权时，不随拥有者一起获得新操作。
- [ ] 未生效、已到期、停用的应用，以及停用的操作仍不能使用。测试后恢复应用状态。

### 03 拥有者字段与目录权限

操作：给普通成员配置手机号等字段的隐藏或脱敏限制，并收窄租户目录可见范围；分别以普通成员和OA查看成员列表、详情、选择器、导出和编辑表单。

- [ ] 普通成员按租户规则隐藏或脱敏；OA可查看租户内完整目录及允许展示的字段，可编辑资源本身支持编辑的字段。
- [ ] 平台强制字段上限、资源只读字段和跨组织边界仍有效。
- [ ] 仅修改浏览器中的拥有者标记，不能让普通成员获得权限。该项由接口联调配合验证。

完成后恢复目录和字段测试配置，以免影响后续范围判断。

## 共享角色与私有角色

### 04 平台创建共享角色

操作：P进入“共享角色”，创建“验收共享角色S”，配置“成员 → 查看成员”等明确操作，预览后保存。

- [ ] 创建和编辑按角色信息、选择权限、设置范围、预览分步进行。预览通过后保存当前权限并立即生效，没有版本名称、版本历史、发布或应用版本。
- [ ] OA、OB的“授权管理 → 角色”中都能找到S，标识为“平台共享”。

### 05 租户只能读取共享角色

操作：OA打开S的基本信息和当前权限。

- [ ] 详情只读，没有修改、停用、删除、复制、继承或定制共享角色的入口。
- [ ] OA仍可将S分配给本组织成员；伪造共享写入请求也会被后端拒绝，由接口联调配合验证。

### 06 共享修改影响两个组织

操作：OA将S分配给MA，OB将S分配给MB；本项让MA、MB只通过S取得待测操作。P为S增加一个操作，随后移除该操作；保持两个租户窗口在线。

- [ ] 两个组织的成员都在下一次对应请求中获得或失去权限，无需重新登录。
- [ ] 可见窗口的菜单、按钮按权限同步；页面没有版本选择、发布、升级或应用版本入口。
- [ ] 已有分配仍是原记录，不需要重新分配人员。测试后恢复S的基础查看权限。

### 07 直接创建组织私有角色

操作：OA创建“验收私有角色T”，直接选择应用、操作和范围，预览后保存；分配给MA。

- [ ] 创建过程没有共享基础、继承、差异或版本选择。
- [ ] 角色标识为“组织私有”；OA可维护，组织B的列表和候选中不能看到或使用T。

### 08 私有角色修改立即生效

操作：MA只通过T取得本项待测操作。OA增加、删除T的一个权限；另测试将权限保存为空。随后恢复测试权限。

- [ ] MA下一次对应请求按修改后的权限执行，无需升级或重新分配。
- [ ] 空权限不会变成全部权限；组织B成员不受T修改影响。
- [ ] 预览中的新增、移除和范围变化与保存内容一致。

### 09 成员分配 用户组分配与多来源

操作：分别将测试角色分配给MA和用户组G；让RA加入、退出G。再给同一成员配置两个都授予待测操作的独立来源，撤销其中一条。

- [ ] 分配选择角色身份，没有版本字段；成员、组和角色回显名称正确，搜索及翻页可用。
- [ ] 加入、退出用户组后，下一次请求按有效组关系执行；组分配也跟随角色后续修改。
- [ ] 撤销一个来源后，另一个有效来源仍然提供权限；所有相应来源撤销后才拒绝该操作。

### 10 停用与删除

操作：让待测成员只使用一个测试角色，停用该角色；尝试删除正在被引用的角色，再创建一个从未分配的空测试角色并删除。

- [ ] 停用后待测角色不再提供权限；恢复启用后按当前权限生效。
- [ ] 被引用角色不能直接删除；从未引用的测试角色可删除。停用、删除共享角色仍只能由平台处理。

## 数据范围与缺失参数

### 11 部门范围确实限制业务数据

操作：移除RA此前直接及组来源。新建范围测试角色，授予“成员 → 查看成员”，选择管理部门范围；分配给RA并绑定“研发”，按需勾选包含下级。

- [ ] RA只能访问研发范围的数据；勾选下级时包含研发子部门，不包含营销或组织B。
- [ ] 修改部门绑定后下一次请求使用新范围；没有静默变成全部范围。

### 12 同资源新增操作跟随原范围

操作：在上述角色增加同一“成员”资源的另一个操作，例如编辑成员，使用同一管理部门参数，不修改原分配。

- [ ] RA自动获得新操作，并仍受研发范围限制；范围外成员不能因新增操作而被访问或修改。
- [ ] 不需要重新选择角色版本或重复绑定同一资源的范围。

### 13 新资源缺范围时安全关闭

操作：为该角色增加另一资源的操作，例如“部门 → 查看部门”，同样选择管理部门范围；暂不为已有分配补新资源参数。

- [ ] 原成员资源的权限仍有效；新增资源缺范围的权限不生效，授权记录能提示待补范围。
- [ ] OA通过普通编辑分配补齐新资源范围后，该操作立即按补齐的范围生效；没有升级步骤。

## 委派授权管理员

开始本组前，撤销RA此前的范围测试分配，并确认DA、RA没有其他角色或组来源提供待测权限。

### 14 创建按资源限制的委派

操作：OA新建“验收委派角色W”，先授予成员查看权限。进入“授权管理 → 授权管理员”，给DA建立委派：角色白名单选W，成员资源上限为研发及下级，接收人限定RA，最长分配时长1小时，来源有效期覆盖本次测试。

- [ ] 委派按角色和资源配置，没有角色版本或逐操作升级步骤。
- [ ] 资源范围、接收人和期限回显正确；角色本身配置全部范围时，委派仍按研发上限收缩。

### 15 仅凭委派完成分配

操作：DA登录，进入授权记录，使用自己的委派来源，为RA分配W，期限不超过1小时及来源到期时间。

- [ ] DA无需额外配置全量角色、成员读取角色，也能搜索、翻页、回显候选并完成预览及保存。
- [ ] 只可选本人有效来源、白名单角色和允许的接收对象；RA的业务数据受研发范围限制。
- [ ] 若另建第二个本人来源，切换后不兼容的角色、人员和范围草稿会被清理，要求重新核对。

### 16 委派不能越权

操作：DA尝试给自己或名单外成员分配、选白名单外角色、扩大到营销、超过授权期限、修改角色、再次委派。使用组分配时，再向组中加入名单外成员。

- [ ] 候选或提交校验拒绝越权；不能借用他人来源，也不能拼接多个来源扩大权限。
- [ ] DA不因委派获得角色编辑或再次委派资格。
- [ ] 组扩大后，名单外成员不会获得权限；不满足来源条件的组分配应失效或提示异常。

### 17 委派跟随角色 但新资源需要上限

操作：OA给W增加同一成员资源的新操作，再增加一个新的资源操作，暂不补该资源的委派上限；随后编辑原委派补齐新资源上限和必要参数。

- [ ] 同资源新操作自动跟随，仍受研发范围限制。
- [ ] 新资源无上限时不生效，并提示缺失；原资源权限保留。
- [ ] 补齐后新资源按上限生效，不需要升级派生分配。

### 18 撤销与到期

操作：OA撤销DA的委派；另用一条短有效期来源观察到期。RA发起新的业务请求，DA尝试继续分配。

- [ ] 来源撤销或到期后，DA相应资格及派生授权失效；没有其他来源时，RA的对应操作被拒绝。
- [ ] 不能借已打开的旧抽屉继续成功提交；失败不会显示为保存成功。

## 刷新 并发与页面交互

### 19 在线刷新与身份切换

操作：保持普通成员页面可见，由另一窗口增删角色权限；再将页面隐藏、恢复可见，并测试退出、切换组织或账号。

- [ ] 本会话保存后立即刷新菜单和按钮；其他窗口不轮询，下一次业务请求立即按新权限执行。
- [ ] 隐藏期间不拉 capabilities；恢复可见且快照已过期后重新核对权限。
- [ ] 退出或切换后，旧身份的迟到响应不恢复旧菜单、拥有者标记或权限。

### 20 并发编辑与错误处理

操作：两个窗口打开同一私有或共享角色，分别改动权限；先保存一个，再提交另一个。另在联调环境模拟权限刷新失败或授权依赖不可用。

- [ ] 并发变化提示重新读取、预览，草稿保留；不会静默覆盖另一窗口的修改，也不要求用户选择业务版本。
- [ ] 授权依赖不可用时不沿用旧允许结果继续执行；SDK接口按约定返回503，前端标记不可用并退避重试。
- [ ] 保存失败不显示成功，失败写入不会自动重放；已保存但权限刷新失败时，提示能区分这两种结果。

故障注入需联调配合；未执行时保留未勾选，不能据普通页面操作认定通过。

### 21 布局与选择器

操作：在宽、窄工作区检查角色、分配、委派抽屉及组织设置；检查空列表、停用角色、搜索无结果、长名称和多选回显。

- [ ] 无横向挤压导致关键按钮或字段不可用；滚动、关闭、返回和草稿离开提示正常。
- [ ] 候选支持分页和独立已选回显，不要求加载全部成员；停用、无权限及范围缺失状态可理解。

## 拥有者转交

### 22 转交后身份与普通分配正确

操作：先给OA单独分配一个普通查看角色并记录。OA在“组织设置”将拥有者转交给有效的本组织成员RA，再分别操作OA、RA的页面。

- [ ] 当前拥有者变为RA；RA无需额外治理角色即可获得有效开通应用全部权限，OA失去动态全权限。
- [ ] OA原有普通角色分配及其权限保留；两个身份的拥有者标记和资格正确刷新。
- [ ] 普通授权管理员不能转交所有权；停用、跨组织目标及过期并发锁不能完成转交，失败不产生部分更新。页面不可选的异常目标由接口联调验证。

## 平台原有功能回归

### 23 平台自有能力保持

操作：P重复此前已完成的平台冒烟用例，重点检查以下项目。

- [ ] 平台自有角色仍保留固定版本、历史查看、字段配置、分配及批量应用任务；本次只将平台共享角色改为当前权限保存。
- [ ] 平台成员、用户组、委派、字段显示和编辑正常，既有任务记录与状态保持。
- [ ] 平台与租户会话互不覆盖；同一账号切换域后，租户拥有者身份不变成平台超级管理员。
- [ ] 本环境若有Member端，原有登录、基本资料及已有业务入口通过冒烟回归。

### 24 接口边界联调

操作：使用对应普通成员或受限管理员的身份，在浏览器网络面板或接口工具中测试越权及旧契约；具体请求字段见 [接口契约](./API.md)。

- [ ] 租户修改共享角色被拒绝；跨组织读取/分配私有角色、成员或部门被拒绝，候选和回显不泄露其他组织记录。
- [ ] 当前租户接口携带旧业务版本、基础或差异字段返回400；已退役的租户/共享版本、发布、升级路由返回410。
- [ ] 不能通过伪造拥有者标记、篡改来源ID或绕过界面范围选择获得权限。
- [ ] 诊断能解释当前角色及真实拥有者来源；授权审计能查到本次保存、分配、委派及转交，历史记录仍保留。
