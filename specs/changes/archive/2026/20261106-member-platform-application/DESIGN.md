# 接入与页面设计

## 平台入口

在 `apps/admin-platform` 增加 `@ingot/member-plugin` 的 workspace 依赖、宿主装配、Vite 官方插件配置及 TypeScript 声明。应用导航沿用 IAM bootstrap 的应用、菜单和操作数据。

IAM 应用编码为 `platform:member`，域为 `PLATFORM`。根目录 `member.root` 使用 `layout.main`，以三个子页读取资格的 ANY 控制显示。应用与根目录使用 `ep:iphone`，子菜单使用现有离线 `ep` 图标集。

| 菜单 | URL | 现有页面键 | 图标 |
| --- | --- | --- | --- |
| 用户管理 | `/member/users` | `member.user` | `ep:user` |
| 角色管理 | `/member/roles` | `member.role` | `ep:avatar` |
| 权限管理 | `/member/permissions` | `member.permission` | `ep:key` |

## 页面

- 三页继续位于 `plugins/member/src/pages/`。复用 `InPageFrame`、`InPageHeader`、`InSplitLayout`、`InTable`、`InTableActions` 和现有表格 ID。标题来自菜单。按列展示状态、标识和层级，查询放在表格工具区。
- 用户页使用现有服务端分页，保留姓名、手机号条件，提交查询回到首页。详情采用 `InDetailDrawer` 及身份、只读和编辑区规范，账号状态复用 `InAccountStatusTag`。删除、重置、停用和锁定沿用各自确认和反馈。
- 角色、权限页消费已有接口树。主列展示节点名称，编码可复制，状态用共享标签。新增、编辑、删除、启停和绑定沿用现有操作语义和服务端限制。
- 两页的操作列固定在右侧，为同一行的「详情」「添加子项」及权限页的「更多」留足宽度。表格横向滚动时操作列保持可见，启停仍从「更多」进入。
- 权限详情的查看和编辑字段使用抽屉正文的内边距，与上方权限名称左对齐。
- 用户角色和角色权限配置采用共享选择录入框、已选标签及独立对话框。复用真实候选树，选择态与筛选结果分开，使用独立关联接口回显绑定。用户角色逐项分配，内置项只读。角色权限保持父子授权语义。确认后提交完整选择，取消丢弃草稿。
- 读取、查询详情、候选、绑定和写动作分别检查 [接口操作码](./API.md)。绑定保存要求相应写操作，同时具备展示已有绑定和候选所需的读权限。

## 后端配套方案

- 按独立平台应用的既有模式增加 IAM 冷启动目录和可预演、幂等的存量库增量。三资源为 `user`、`role`、`permission`，复用 Member 控制器现有精确操作码，范围为 ALL。升级按自然键校验归属及冲突，保留已有目录标识、已发布角色版本和授权分配。既有普通角色通过正常发布、分配流程获得权限。
- Member 平台管理接口接入现有 IAM 在线授权能力及当前平台身份校验。参考安全中心的全局资源门禁，核对真实平台会话经过网关后的授权和改密状态恢复。拒绝缺少精确权限、租户身份和无法确认授权的请求。保持 Member 业务数据和 HTTP 接口形态。
- 存量库使用后端 036 增量，回滚禁用应用并刷新授权与路由缓存，保留已有授权引用。发布联调使用已准备的测试库，覆盖冷启动、存量升级、权限矩阵及三页业务流。

## 宪章符合性

宿主只装配插件，业务页面和类型留在 Member 插件。继续使用共享 UI、Vue 3、TypeScript、UnoCSS 和 pnpm，沿用现有 API 封装及请求契约。
