# 持久化账本读取性能续验（2026-11-14）

结论：**未达到批准的性能门槛，发布阻断保持**。三节点 GR 恢复后，candidate10 在保留审计积压、200 次预热及无并行验收负载下进行 1000 次真实 AT 权威接口请求。默认配置 P50 23.49ms、P95 60.05ms、P99 90.61ms；门槛为 P95≤15ms、P99≤50ms。

非终止线程采样观察到 JDBC 往返及 Druid SQL 统计参数化开销。只在隔离 Auth1 做同一代码的临时对照：JVM 关闭统计 SQL 合并时 P95 43.14ms、P99 65.31ms；再加入 JDBC 本地协议状态与连接池默认 READ_COMMITTED 时 P95 44.24ms、P99 70.23ms。两组仍失败，不能据此发布，也不能证明所有候选参数均实际生效。临时 JVM/数据源配置均已撤回，恢复原运行时管理的 Auth1；没有把对照参数写入仓库配置。

原吞吐基线、峰值/2倍突发、集中 refresh、冷缓存、outbox 积压与 CPU/连接池余量尚未完成，不用本组空闲串行采样替代。后续优化仍必须保留权威在线读取、完整密文校验、强一致屏障及最终数据库 UTC 截止判断，不使用正向身份缓存或故障放行。

脱敏原始指标见 [JSON](LEDGER-PERFORMANCE-CONTROLS.json)。故障恢复与容量边界另见 [容量记录](LEDGER-CAPACITY-RECOVERY.md)。

运行规格补记：Multipass实测三VM各1vCPU；JVM显式ActiveProcessorCount=1，线程转储确认Serial GC。现有指标只代表该隔离规格；生产规格对照、吞吐及资源余量仍未验证，不据此修改批准门槛。
