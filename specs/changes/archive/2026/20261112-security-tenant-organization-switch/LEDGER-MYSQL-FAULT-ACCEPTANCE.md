# 真实 MySQL GR 故障验收（candidate8）

三台用户授权的独立内核 VM，同一物理宿主。实际网络规则、容器 SIGKILL、RPO0 选主与旧成员重入；应用保持持久权威校验，无 JWT-only 或缓存放行。原始脱敏结果见同名 JSON。

| 场景 | 结果 |
| --- | --- |
| 已确认切换/退出/RT 撤销后，实际主节点 SIGKILL 并选主 | 通过；旧 Cookie401、旧RT400、resume拒绝且无Set-Cookie；恢复后仍拒绝 |
| 旧主 TCP 存活但与多数派分区 | 通过；来源节点身份、内部结果和RT返回503；多数派身份和RT正常；重入后实际Cookie仍为同一结果，原来源查询401 |
| 三节点复制通信全部分区，业务TCP存活 | 通过；两端身份、RT、结果查询503；恢复就绪后同一sid/token/代次与原绝对截止不变，结果会话数量1 |

恢复先核对三节点同视图 ONLINE，再以有界只读身份探测等待 Auth 连接池恢复；该阶段可观察到503，不重放写请求。已经确认交付的Cookie用于验证恢复后的实际身份；内部签发结果查询只适用于尚未激活候选，已撤销来源返回401属于安全契约。

前两次脚本失败分别为误用已撤销来源查询已完成结果，以及数据库ONLINE早于应用连接池就绪；观察保留，未放宽产品行为，未计入本批通过。正常成员追赶/Clone保持原incarnation，与备份恢复后生成新incarnation是不同门禁；后者仍待验。

其余R1/R2最终包20轮、总计1000次竞争、固定root RT、C02故障点、性能、发布回滚及最终清理仍未完成。发布阻断保持，未提交。
