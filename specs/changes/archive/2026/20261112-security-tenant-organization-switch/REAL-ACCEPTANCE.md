## 环境与真实性

- 独立 JVM：IAM、Gateway 各 1 个，Auth 与 BFF 各 2 个，共享临时 Redis 8.2.0 和 MySQL 8.4.13；每次运行重新导入仓库种子库。
- 通过真实 IAM 加密 API 建立验收账号、组织 A/B、不同成员与根部门；完成实际初始密码修改。浏览器从真实 BFF 登录页输入密码并选组织，未注入 token 或正式会话 Cookie。
- 前端使用两个管理端的构建产物，Chrome 经同源 HTTPS /api、真实 Gateway/BFF/Auth/IAM 运行。设备指纹、精确 Origin、CSRF 和上下文版本正常校验。
- 最终验收保持种子库 BFF 客户端 UNIQUE 单会话策略（MySQL 实际值 1），未为竞争场景放宽策略。BFF 原登录截止设为 90 秒，来源 AT 配置为 300 秒，以观察切换结果被原登录截止截断；没有修改系统时钟或缩短已创建会话 TTL。
- HTTP 故障代理仅控制真实请求的调度、延迟和响应丢弃，不生成业务响应。两个运行批次的四个服务包 SHA-256 完全一致。

## 场景与实际结果

| 场景 | 操作和证据 | 结果 |
|---|---|---|
| A→B→A | 实际点击菜单切换，无密码重输；三次 sid 摘要不同，A/B 成员和部门不同，回 A 恢复正确成员/部门；原生另一标签资料随组织更新；me 截止不变 | 通过 |
| 双标签竞争 | 两个真实标签分别创建事务，向不同 BFF 节点同时提交；仅一个 200/COMPLETED，另一个 409；只有一个正式结果；两页重验后进入 B；旧版本写请求 409 | 通过 |
| 退出并发 | Auth 已实际签发后暂扣回包；BFF0 等待结果时，在 BFF1 执行真实菜单退出，再释放结果；提交 403、不写正式 Cookie，旧事务 resume 403，原 sid 撤销；未采用结果有持久清理记录且截止受来源约束 | 通过 |
| 丢响应恢复 | 丢弃 BFF0 成功提交后的响应；浏览器从 BFF1 resume，200 恢复同一结果；Auth 只签发一次，sid 摘要和公开事务版本均与原结果一致 | 通过 |
| 原登录截止 | 新登录后连续 B→A，AT/BFF/Cookie 协议截止均不突破原期限；等待真实 90 秒自然到达，me 401，显式重放过期 Cookie 仍 401，过期事务读取 410 | 通过 |

正常往返验证的是原生 UI 跨页同步。确定性双标签竞争使用两个浏览器标签发起真实认证 API，确保请求在前端暂停前同时进入两个 BFF，随后两页重载验证胜出身份；它不替代全部“同时点击 UI”的交互矩阵。

初次轮询拓扑中，退出和恢复的关键请求恰好落在同一 BFF。核对逐请求记录后，另起同包隔离环境，强制切换提交走 BFF0，退出和 resume 走 BFF1，并以实际 node 字段断言不同节点；上述表格的跨节点结论来自这次补充实证。

## 本轮发现与修复

- F03：审计段插入破坏 BFF YAML 缩进并产生重复根键。恢复 account.bff、security.event、bff 的正确结构；DEV/TEST/PROD 严格重复键检查通过，两台真实 BFF 导入 DEV 配置启动通过。
- F04：预授权的凭证校验误用 password grant 准入，种子库公开 BFF 客户端无法真实登录。使用服务端专用请求子类型按已授权 pre_authorization_code 校验，保留密码/账号检查；不向 BFF 增授 password grant。另修复缺少已认证客户端时的空指针，改为 invalid_client。新增 5 个准入回归；实际直接 password HTTP 请求返回 401/invalid_client，未产生新身份。
- F05：相对 Max-Age 在浏览器接收响应后计时，取整与传输延迟造成 Cookie 截止漂移。正式 Cookie 改为固定 UTC HTTP-date Expires，不附加正 Max-Age。定向测试验证切换与延后恢复的 Expires 完全相同；真实提交/恢复的 5 条 Cookie 线协议记录均等于原截止。Chromium API 呈现小数秒本地估计值，报告同时保留协议值和自然截止后的实际拒绝结果。

未采用的迟到签发有持久清理记录，并受原截止限制；没有将“立即撤销”作为已通过结论。完整五场景结束时，测试账号在线会话、租户正式 BFF 会话、清理载荷与到期索引均为零；补充环境也已删除。
