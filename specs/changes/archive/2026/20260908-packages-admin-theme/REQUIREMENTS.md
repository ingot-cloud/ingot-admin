# 需求：可扩展管理台主题

## 用户场景

1. 项目开发者安装符合协议的主题包，在 admin 启动配置中选择主题，重新构建部署后获得统一外观；不修改业务插件或后端菜单。
2. 主题开发者通过公开 Token 和 CSS 接口调整配色、字体、圆角、间距等，通过布局插槽重新排列顶栏、导航和内容区，并按需替换展示部件。
3. 默认后台沿用现有主题，使用者仍可切换浅深色；已有页面操作、设置偏好和响应式行为保持可用。
4. 项目继续注册专用工作台等 layout。这些布局继承全局主题 Token，自主决定是否组合主题布局宿主；选择主题不自动替换其结构。
5. create-app 创建的新后台显式选择默认主题；开发者按相同方式更换为自定义主题。

## ADDED

### REQ-A001：主题包与显式配置

- [x] 支持本地 workspace 包和 npm 包；主题不需要业务插件注册或后端接口。
- [x] admin 与脚手架生成应用显式配置主题；未配置主题的已有应用回退到默认主题。
- [x] 主题协议版本不兼容时，在应用挂载前给出包含主题标识的中文错误。
- [x] 无主题选择页面，不保存用户级主题 ID；主题选择由应用代码决定。

### REQ-A002：视觉协议

- [x] 提供类型化 Token、稳定 CSS 变量及附加 CSS 作用域规范；可覆盖基础、语义、组件外观。
- [x] 默认主题保留现有浅深色视觉；自定义主题省略的 Token 和部件继承默认值。
- [x] 主题与明暗模式独立；切换明暗不更换主题，刷新保留现有明暗偏好语义。
- [x] 页面、导航、弹窗、下拉、Toast 均使用生效主题；浅深色样式不存在相互覆盖失效。

### REQ-A003：主题布局

- [x] 主题可重排顶栏、导航、标签栏、面包屑、内容区、页脚，支持替换内容区以外的展示部件。
- [x] 核心负责路由出口、KeepAlive、滚动恢复、菜单与权限数据、设置可见性和窄屏导航状态；主题通过公开协议访问状态和操作。
- [x] 内容插槽只渲染一次；标准页面和独立滚动区域正常工作，无新增双滚动条。
- [x] 自定义布局遵守窄屏导航关闭、遮罩、Escape 和键盘可访问性契约。
- [x] 现有 header-start、header-end、sidebar-top、sidebar-bottom 扩展点在默认和自定义主题中均有效。

## MODIFIED

### REQ-M001：固定主布局改为主题宿主

相对现有 UI 基础规格，固定视觉值及顶栏/侧栏排布成为默认主题的行为基线；自定义主题允许通过协议改变外观与编排。

- [x] 核心 `layout.main` 标识保持稳定，菜单及静态路由不需要按主题迁移。
- [x] 上层 layouts 扫描、布局键生成、列表展示和重复键报错行为保持不变。
- [x] 项目独立 layout 不被主题隐式替换；需要主题外壳时可使用公开布局宿主。
- [x] simple、iframe、external 布局的路由语义不变；第一版不提供这些布局的主题替换入口。

### REQ-M002：后台脚手架与默认兼容

- [x] admin 和 create-app 使用同一主题接入协议。
- [x] 保留 `@ingot/admin-core/style.css` 入口、旧 Token 别名和已有未配置主题应用的默认外观。
- [x] 不改变 apps/auth 的主题接入或界面。

## 综合验收

- [x] 使用一套示例主题同时证明配色覆盖、顶栏替换、区域重排和独立包消费成功。
- [x] 切换路由、返回已缓存页面、滚动位置恢复、菜单权限、明暗切换、全局设置和窄屏交互通过回归。
- [x] 默认主题与自定义示例均完成桌面/窄屏、浅色/深色检查。
