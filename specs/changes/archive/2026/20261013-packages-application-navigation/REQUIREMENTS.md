# 需求：顶栏多应用导航

## 用户场景

1. 只有一到两个可访问应用时，顶栏直接展示应用图标与名称，点击切换。
2. 超出直出数量时，最后一个快捷应用右侧出现下拉箭头；hover 整个入口展开分类面板，点击箭头也可展开。
3. 用户从面板选择其他应用，进入该应用首个可导航菜单，侧栏和当前应用高亮同步。
4. 窗口变窄时，直出数量可以低于配置上限，当前应用保持可见，更多应用仍能访问。
5. 宿主调整直出数量、分类标题或应用归属，无需修改核心组件和后端接口。

## 规则

### AN01：默认数量与配置

- `navigation.source = "applications"` 时，`maxVisibleItems` 未配置默认 2。
- 显式配置正整数数量，作为直出上限；宽度不足继续收纳，可导航应用非空时至少直出一个。
- 小于 1、非整数、非有限数等无效数量统一回退应用默认值，避免异常收纳。
- 当前应用优先保留，其余按 bootstrap 的 sortOrder 和稳定 id 顺序填充，展示顺序沿用现有规则。
- configured 模式未配置数量仍只由宽度决定，保持既有兼容性。

### AN02：最后入口与箭头

- 存在溢出应用时，最后一个可见应用以“图标、名称、下拉箭头”连续展示，应用模式不再为溢出应用单独放「…」。
- 应用名称区域点击切换应用；箭头是独立按钮，点击仅展开或收起面板，不触发应用切换。
- hover 整个组合入口默认展开；进入面板保持打开，离开触发区及面板后延迟 160ms 关闭。
- 展开时组合入口出现浅灰背景，箭头向上；关闭时箭头向下。选中应用保持现有中性高亮。
- 没有溢出应用时不显示箭头；只有一个应用但因宽度不足收纳旧插槽时，旧插槽仍有可访问的更多入口。

### AN03：分类面板

- 展示溢出应用，已直出的应用不在面板重复。
- 分类标题为灰色文字，下方细分隔线横跨该组所有列；组内入口为图标和名称，并按列优先布局。
- 分类标题、归属和可选 columns 在前端 `navigation.applicationGroups` 配置，按稳定应用 code 匹配，不绑定环境相关应用 id。
- 分类顺序跟随配置，组内应用顺序沿用 bootstrap 排序；空分类不渲染。
- 未配置分类时统一展示“应用”；配置分类后，未匹配应用进入最后的“其他应用”。
- 配置了未知、未授权或没有可导航菜单的应用 code 时不产生入口；重复分类 key 或跨分类重复应用 code 显式校验失败，避免同一应用出现多次。
- 未指定 columns 时复用每列最多 8 行、最多 4 列的折列规则；列数基于实际溢出条目计算。
- 桌面分类横向排列，空间不足可换行；窄屏单列，面板限制在视口内并可纵向滚动。
- 应用图标支持现有 Iconify 或图片地址，缺失或加载失败时沿用默认图标。

### AN04：切换与授权

- 从面板选择应用仍调用现有应用导航选择链路，不额外拉取应用全量或改写授权路由。
- 切换成功后当前应用优先进入快捷入口；例如 A/B/C 默认直出 A/B，选择 C 后直出 A/C，B 进入更多。
- 刷新、深链接及搜索导航保持路由、顶栏高亮和侧栏同步；路由未成功切换时不提前伪造高亮或应用上下文。
- 权限或 bootstrap 更新后，失效应用不得残留在打开的面板中。
- 强制改密状态继续不挂载导航及面板。

### AN05：可访问性与兼容

- 箭头具备“更多应用”可访问名称、aria-expanded 和面板关联。
- Enter / Space 操作箭头；Escape 或点击外部关闭；键盘关闭恢复箭头焦点，面板内应用通过 Tab / Enter 可选择。
- hover 打开不抢夺当前键盘焦点；点击及键盘打开允许进入面板。
- 打开搜索或小部件面板时与应用面板互斥。
- configured 模式的 Action / Group、hover / click、选择 payload、旧插槽和自定义 header 主题协议保持兼容。
