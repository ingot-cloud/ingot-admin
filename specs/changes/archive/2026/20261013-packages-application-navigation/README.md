## 协作模式

前端交互优化，复用现有 IAM bootstrap，不新增或修改后端接口。

## 背景与动机

平台管理台已配置最多直出两个应用，但溢出应用通过独立「…」按钮进入单列列表。现有手工菜单的分类面板已具备灰色标题、分隔线和组内多列布局，应用模式尚未复用。用户要求参考飞书，把更多入口整合到最后一个快捷应用右侧，并在 hover 时展示分类应用面板。

## 目标与范围

- 应用模式默认直出上限为 2，继续允许宿主配置具体数量及按宽度进一步收纳。
- 有溢出应用时，在最后一个快捷应用右侧显示独立可交互箭头，整项 hover 展开，名称和箭头各自保留明确点击语义。
- 溢出应用复用现有分类、多列、图标与文案布局；分类通过前端配置按应用 code 匹配。
- 保留当前应用优先、路由与侧栏联动、授权过滤、图标回退及强制改密限制。
- 本次改动位于 admin-core、平台宿主配置及工程文档；普通 configured 导航沿用原行为。

不涉及后端分类模型、应用管理页面、授权变更、拖拽排序、常用应用持久化或整个管理台的视觉改造。

## 风险与依赖

- 集成箭头的真实宽度必须纳入收纳测量，防止提前收纳、临界抖动或重叠。
- hover 的触发区到浮层之间存在间隙，需要延迟关闭并在进入面板时取消，保证菜单可点。
- 分类配置只能重排已授权且有可导航菜单的应用，不能产生新的可访问入口。
- 人工验收完成前保持 active，不提前更新 current 或归档。
