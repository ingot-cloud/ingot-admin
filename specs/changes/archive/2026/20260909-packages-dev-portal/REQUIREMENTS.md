# 需求：Ingot 开发者中心

## 用户与成功标准

面向使用和扩展本 monorepo 的前端开发者：能够查清框架如何使用、开发和扩展，通过向导创建有效的 App／插件／主题，并依据生成后的步骤完成组合运行。现有普通后台仍优先使用 apps/admin。

## REQ-001：统一门户

- 应用目录及包名更名为 apps/dev-portal、@ingot/dev-portal，首页展示「Ingot 开发者中心」。
- 使用 VitePress 默认主题扩展，提供首页、分组导航、侧栏、页内目录、中文全文搜索、代码复制、明暗模式和窄屏布局。
- 导航覆盖快速开始、App 开发、插件开发、主题开发、组件、公共能力、工程与部署、创建工具。
- 本地默认地址保持 http://127.0.0.1:5801；构建产物可在站点根路径或配置的子路径静态部署。
- 旧根命令保持可用；直接按旧包名 filter 的用法更新为新包名，不保留第二个空壳 workspace 包。

## REQ-002：完整文档与交互演示

- 覆盖全部框架公开能力：公共包 exports、框架注册的全局组件、公开 hooks／stores／指令／工具、配置接口、插件协议、主题协议与 Token。公开类型允许与其所属能力合并说明，不要求每个类型独立页面。
- 组件说明必须包含用途、依赖与导入方式、Props／事件／插槽／公开方法（不适用时注明）、示例及使用限制。模块说明包含输入输出、典型流程、错误处理和扩展边界。
- 指南说明 App 配置和定制、环境变量、登录、菜单权限及 view_path、路由布局、页面四件套、查询分页、网络拦截器、加密、状态持久化、顶栏、图标、主题开发、公共包扩展、测试及部署。
- 四个官方插件说明各自模块功能、依赖、配置及接入步骤；auth 单独说明运行和配置。第三方库只解释框架集成与差异，通用 API 链接其官方文档。
- 每个可独立运行的公开 UI 组件至少提供一个可交互在线示例，可通过组合示例覆盖多个组件；源码与演示同源。复杂布局提供有界尺寸的示例。
- 依赖网络、上传、身份或运行时上下文的示例使用固定模拟数据与最小上下文，明确真实接入方式；不发起真实业务请求、登录跳转或上传。
- docs 和包内参考文档保持单份正文；覆盖清单中的每个条目必须对应有效章节。未完成页、仅列出名称、TODO 和空目录不算覆盖。

## REQ-003：向导公共流程

- 三种类型分别有稳定入口：/create/app、/create/plugin、/create/theme。
- 依次配置、预览文件树与关键文本、生成、展示接入步骤；可返回修改，修改后旧预览失效。
- 字段具备中文说明、默认值、校验反馈和文档链接；显示最终目标目录与包名。
- 本地预览不写目标目录；创建前重新校验仓库状态，不覆盖已有目录。提交中禁用重复操作，失败保留输入并显示可处理的错误。
- 静态部署时显示配置说明及本地运行指引，不尝试调用本地文件 API；默认配置可浏览，不承诺线上实际生成或下载。
- 用户配置只保留在当前页面内存；不默认写 localStorage、URL、日志或文档构建产物。

## REQ-004：创建 App

- 生成 apps/<appCode>，编码、品牌、端口、环境文件、运行时、构建代理及扩展点按 CONFIGURATION.md 覆盖。
- 全部现有 App 环境变量可编辑，支持公共文件、development／production 与自定义 mode 覆盖，以及新增合法变量；展示最终文件归属和生效值。
- 四个官方插件默认全选，也可选择其它仓库源码插件或全部取消；依赖、plugins.ts、类型配置及 Vite 编译清单必须一致。
- 默认主题为 defaultAdminTheme；可选择仓库已有主题，自动生成对应 dependency、主题 import 与 CSS import。
- 始终生成约定本地插件；Demo 开关只控制示例内容。复杂配置通过有类型且被入口引用的扩展文件交付。
- Docker、代理、图标清单、二进制资源和安装启动说明均有效；不把宿主真实 .env.local 或用户凭据复制到模板。

## REQ-005：创建插件

- 生成 plugins/<id>，默认包名 @ingot/<id>-plugin；可配置插件 ID、导出名、canonical prefix、说明和示例能力。
- 提供空骨架和 Demo，按需加入页面／静态菜单、布局、Biz 组件、指令、store、install 扩展。列表示例采用页面四件套。
- 生成源码导出与 type-check、test:unit、lint 配置；不提供独立 HTML、dev、preview 或 production build。
- 默认依赖 ingot-admin-core；不提供跨业务插件依赖选项。接入指引明确宿主依赖、注册、构建扫描、安装及菜单配置。

## REQ-006：创建主题

- 生成 themes/<id>，包名 @ingot/theme-<id>；可配置名称、导出名、全部公开 Token 的明暗覆盖，以及可选 Shell 和 parts 扩展示例。
- 默认仅 Token，省略的明暗项分别继承对应模式默认值；不将浅色覆盖自动复制到深色。
- 扩展示例遵循 content 恰好一次、有界滚动区、开关、shellSlots、窄屏 overlay／Escape 等核心契约。
- 主题提供 JS、声明、CSS、资源构建产物与 build／type-check／test:unit／clean 脚本，CSS 有作用域和 sideEffects，运行时 peer external。
- 创建完成不会启用主题或改现有 App，提供准确接入与回退默认主题步骤。

## REQ-007：生成器与工程闭环

- Web 和 CLI 共用描述、校验、预览、生成逻辑；CLI 支持 JSON 配置输入，旧 App 参数及交互用法保留。
- 拒绝非法标识、路径逃逸、符号链接绕过、覆盖和并发重复创建；不执行用户输入代码或生成后的命令。
- 自定义插件能在 App 内正确处理 @/、Vue SFC、glob、自动导入、UnoCSS、Iconify 和 optimizeDeps；未选插件／主题不进入 App 模块图。
- 根检查覆盖门户构建、文档链接、公开能力清单、示例类型、生成器与组合产物；不修改既有业务行为来迁就文档演示。

## 验收矩阵

| 场景 | 预期结果 |
| --- | --- |
| 本地进入门户 | 搜索、导航、三个向导可用，写入能力明确 |
| 静态根路径及子路径部署 | 文档、资源、搜索和演示可用，无本地 API 请求 |
| 默认／零插件／无 Demo App | 产物可类型检查和构建，本地约定插件始终存在 |
| 多环境及自定义变量 | 公共与 mode 覆盖正确，env 转义后值不改变，UI 与生成文件一致 |
| 创建插件 → 创建主题 → 创建 App 并选择二者 | 组合构建、样式、注册与依赖边界通过；已有 App 文件不变 |
| 自定义插件内部使用 @/、glob、hook 与图标 | 开发和构建均解析到该插件，不串宿主路径 |
| 主题 Token／Shell／parts 组合 | 明暗独立生效、CSS 有作用域、公开产物可消费 |
| 非法输入、已有目录、符号链接、并发、写入故障 | 中文错误；不覆盖他人目录，不遗留本次半成品 |
| 所有公开能力查阅 | 均有有效使用章节；可独立运行组件有交互示例及同源源码 |
| 桌面／窄屏、浅色／深色 | 导航、表单、预览和 iframe 无页面级横向溢出；代码块内部可滚动 |
