# 需求：账号保护 · 账号锁定

> 无既有 `current/` 规格，本次为新页面。接口字段见 [API.md](./API.md)。

## 场景与页面

### 场景 1：查看 B / C 两端锁定策略

- **角色**：平台管理员（菜单进入需 `platform:security:account:lockout:query` 或超级管理员）
- **入口**：安全中心 → 账号保护 →「账号锁定」Tab
- **步骤**：打开页面，默认落在账号锁定 Tab；左右两栏分别展示 B 端管理员、C 端会员的当前策略
- **预期结果**：进 Tab 一次拉取全部策略（固定 2 行）；缺行时该栏为空态/可提示，不伪造提交

### 场景 2：分别保存某一端策略

- **角色**：平台管理员（写操作需 `platform:security:account:lockout:update` 或超级管理员）
- **入口**：某一栏的「编辑 → 保存」
- **步骤**：修改启用开关、失败次数、锁定时长、滑动窗口、提示起始次数、备注 → 确认保存
- **预期结果**：只 PUT 该栏对应 `userType`，另一栏不受影响；成功提示「账号锁定策略将在数秒内生效」；已锁定账号不会因此自动解锁

### 场景 3：永久锁定仅对 B 端开放

- **角色**：平台管理员
- **入口**：B 端栏可勾选「永久锁定」；C 端栏不提供该选项
- **步骤**：B 端勾选永久锁定后时长视为 `0`；C 端只能填 ≥ 1 的分钟数
- **预期结果**：C 端无法提交永久锁定；B 端允许 `lockDurationMinutes = 0`

### 页面结构

```text
安全中心
└── 账号保护              ← 单页菜单
      └── Tab：账号锁定   ← 本期唯一 Tab；后续能力继续加 Tab
            ├── 左栏：B 端（管理员）  userType=0
            └── 右栏：C 端（会员）    userType=1
```

- 建议路由：`/platform/security/account-protection`
- 每栏独立：启用开关、失败次数阈值、锁定时长（分钟）、失败计数窗口、提示起始次数、备注、最近更新时间
- 每栏自有编辑 / 取消 / 保存；无新增、无删除、无强制刷新
- Tab 内提示：策略数秒内生效；已锁定账号不会因本次保存自动解锁

## 验收标准

- [x] 菜单为「安全中心 / 账号保护」单页；账号锁定是页内 Tab，不是子菜单
- [x] 账号锁定 Tab 左右两栏，分别对应 B 端 / C 端，进 Tab 一次 GET 列表即可
- [x] 两栏分别 PUT，禁止合并成一次请求
- [x] 无新增按钮、无删除按钮
- [x] B 端可勾选永久锁定（`lockDurationMinutes = 0`）；C 端隐藏或禁用该选项，且时长 ≥ 1
- [x] `maxAttempts` ≥ 1、`attemptWindowMinutes` ≥ 1、`1 ≤ hintAfterAttempts ≤ maxAttempts`
- [x] 保存成功提示「账号锁定策略将在数秒内生效」
- [x] 无更新权限时隐藏编辑/保存，只读展示
- [x] 不调用 Inner Feign；前端不传 Bearer Token
