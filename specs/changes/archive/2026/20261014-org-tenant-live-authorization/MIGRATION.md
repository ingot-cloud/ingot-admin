# 前端契约切换与回滚

## 权威来源与职责

数据库预检、冲突处置、正逆转换及备份由后端与发布责任方执行，原文副本见 [BACKEND_MIGRATION](./sources/BACKEND_MIGRATION.md)。前端不提供迁移按钮，不在浏览器把旧版本分配猜成roleId，不消费未验证迁移结果。本轮已构建两个管理台及公共包，隔离迁移回滚证据见VALIDATION；未发布或访问实际数据库。

## 1. 开发与迁移准备

1. 核对API.md与后端权威文件SHA-256，建立当前角色/分配/资源委派类型与接口。旧平台自有DTO仍保留；org和共享来源退出的API调用必须清理。
2. 基于后端隔离迁移数据验证共享当前权限、物化后的私有角色、旧不同版本统一最新、缺参数冲突、SYSTEM历史处置以及委派异范围转换。
3. 确认平台自有固定版本/字段/任务页面可用；当前源代码曾有隐藏入口、旧版本文案或未接完整流程，不能仅凭静态删除完成验收。
4. 生成平台/租户App和公共包的一致制品，记录版本及API来源摘要，保留上一套可部署制品。制品不得把Spec状态标为已验收。

## 2. 维护窗口切换

| 步骤 | 前端动作 | 后端依赖/退出条件 |
|---|---|---|
| FP01 | 旧管理台授权写入口停止，维护提示不自动重发草稿 | 后端冻结写入与完整备份已确认 |
| FP02 | 等待后端结构/数据转换与校验 | 无未决冲突，当前角色/稳定分配/资源委派数据可用 |
| FP03 | 部署新平台和租户制品，清除旧入口缓存与失效静态资源 | 全部IAM与授权消费SDK同一目标规则，无旧新租户API混用 |
| FP04 | 已有有效会话拉取新capabilities/bootstrap，替换动态菜单 | ID/context仍相同，不要求重新登录；异常显示不可用而非旧契约兜底 |
| FP05 | 授权写仍冻结时验证拥有者、共享/私有、委派及平台旧能力 | U矩阵/B矩阵及性能、迁移报告通过，window内回滚可用 |
| FP06 | 放开写入并记录起点，保留新旧制品和来源 | 后端逆转换已演练，不能只靠回退前端回滚 |

旧租户版本/升级路由返回410；前端不得 fallback 到历史RoleRevisionRef、旧publish或baseRevisionId。浏览器本地保存的旧授权草稿标记不兼容，请用户按当前角色重新选取，不能自动保留不明scope参数。

组织/身份切换使用contextEpoch清理异步响应。菜单重载只替换当前会话，不清掉同账号另一个平台/租户origin的会话。预检/迁移清单仅由有权限人员查看，不在普通租户UI展示其他组织变化。

## 3. 回滚

观察窗口未产生新授权写入时，停止新界面写入，配合后端备份还原与原API恢复，再部署原前端、清静态缓存、重新bootstrap验证。禁止只把前端回退到依赖版本接口的页面而仍接新后端。

开放新模型写入后，停止两端写入并保留当前制品/数据；等待后端P10逆转换完成及校验通过，再部署旧平台/租户制品。逆转换失败保持维护，不以旧接口或当前页面模拟旧权限。回滚将恢复旧固定版本授权行为，发布说明明确这一功能差异；用户在新模型中创建的角色、分配、委派、转交和审计必须由后端保留。

前端回滚验收包括：技术版本和业务版本含义重新匹配旧契约、原menu注册可用、当前owner显示与后端一致、无双timer或迟到新契约响应、平台固定任务状态保留。所有失败和回滚步骤记录时间、制品摘要及结果。

## 4. 验收与资料

至少完成一次迁移fixture上的两管理台浏览器演练，以及一次新增授权写入后的联合逆转换/前端回退演练。保存源文件摘要、制品清单、U01–U16结果、后端B17–B20/B24对应报告和操作顺序。构建成功、接口Mock通过不代表正式切换完成。

## 5. 当前未上线测试环境的简化入口

用户已确认系统未上线、租户尚未测试，且021已执行/022失败。此环境停止IAM后直接运行后端 `databases/iam/dev/prepare_tenant_live_test.sql`；脚本停用旧租户授权、保留平台事实和共享最新范围，并自动安装022，无需导出/preflight/forward/verify。返回TENANT_LIVE_TEST_READY后重新编译启动新版IAM/SDK和两管理台、刷新浏览器，按VALIDATION用户验收重点测试。已创建的新模型测试数据重跑不重置；生产保留数据的原迁移/回滚流程继续适用。
