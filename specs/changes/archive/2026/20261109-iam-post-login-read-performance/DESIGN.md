# 设计

两域组列表增加 view=SUMMARY，沿用默认完整信封、原分页、排序和筛选。摘要使用同一组对象范围，只返回元数据、版本和操作能力。显式只读列表接入请求内授权上下文。空页跳过组能力及关联装配。完整页按当前页组 ID 读关系，使用既有成员和部门范围投影，在 MySQL 按组聚合去重后的有效成员。写入沿用独立校验及乐观锁。

两端组工作区和选择器走摘要，独立成员分页。查看及编辑读取目标组详情，完整编辑按详情能力和版本提交，选择变化时丢弃旧结果。

场景错误限 IAM。应用域及部门查询用途缺失或无效、组 JSON 格式错误返回 400 InvalidArgument。空组名沿用原业务码。指定对象详情的默认 404 文案增加类型，保持 ObjectNotFound 和可见性边界。

数据库沿用现有结构及索引，缓存沿用现行策略。先发布兼容后端再发布前端，回退反向执行。

重点写入入口以接口 message 为失败原因。前端已有对象名称时，在就地提示中带上操作与名称。通过 silent 交给编辑器或确认框的请求只由该入口展示一次，普通全局请求由现有提示层展示，拒绝时保留草稿及现有权限刷新语义。

共享 HTTP 客户端将旧服务的通用内部错误和无业务码的 5xx 归一为固定中文提示并丢弃附带诊断数据，已知 IAM 和认证业务码仍按原规则处理。
